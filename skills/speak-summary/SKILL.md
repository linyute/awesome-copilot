# 語音摘要 (Speak Summary)

將書面文字轉化為人們真正想聽的音訊。

此技能刻意被設計為**鏈結中的終點步驟**。由另一個技能（或你）產生文字；此技能則讓它適合聆聽。它能自然地與 `roundup`、`daily-prep`、`meeting-minutes` 或任何摘要工作搭配使用。

一切都在本機 CPU 上執行。沒有文字會傳送至雲端語音服務，當內容機密時這一點尤為重要，這也意味著此技能在無前端的雲端代理程式或 CI 容器中運作得和在筆記型電腦上一樣好。

## 先決條件

合成引擎為 [Kyutai `pocket-tts`](https://github.com/kyutai-labs/pocket-tts)，這是一個專為在 CPU 上執行而設計的小型神經 TTS 模型。

隨附的指令碼會在初次使用時自動將其安裝到快取的 virtualenv 中，因此通常你不需要做任何事。若要明確安裝它：

```bash
pip install pocket-tts          # 任何平台
brew install pocket-tts         # macOS，若偏好使用
```

`pocket-tts` 需要 **Python >=3.10 且 <3.15**。該指令碼會搜尋相容的直譯器，而不是直接假設 `python3` 即為相容直譯器 — 若你使用的是非常新的 Python 版本，這點值得了解，否則安裝可能會失敗。

你還需要一個編碼器。強烈建議使用 `ffmpeg`（`brew install ffmpeg` 或 `apt-get install -y ffmpeg`）；在 macOS 上，該指令碼會回復使用內建的 `afconvert` 並發出 `.m4a` 而非 `.mp3`。

首次執行會從 Hugging Face 下載模型 (~1GB)。之後即完全離線，且合成速度約比即時 (real-time) 快 6 倍。

## 重要步驟：為耳朵重寫

**請勿將書面文字直接餵給合成器。** 在螢幕上閱讀流暢的散文，聽起來會讓人疲倦。先進行重寫，是將實用的口述摘要與難以聆聽的內容區分開來的關鍵。

產生一份符合以下條件的口語稿：

- **以導向作為開場。** 說明這是什麼、涵蓋什麼內容、大約需要多長時間。
- **以銜接性的散文取代項目符號。** 「第一… 更大的一點是… 最後…」— 聆聽者沒有視覺結構可以依賴，因此請用語言來承擔這個功能。
- **首次使用時展開縮寫。** 「PR」變成「pull request」，「CI」變成「continuous integration」。閱讀起來沒問題的縮寫字，在唸出來時會變成噪音。
- **自然地說出日期和數字。** 說「八月二十日」，而不是「2026-08-20」。說「大約三千」，而不是「2,847」。
- **切勿大聲朗讀 URL。** 改為說「連結在書面版本中」。
- **使用短句。** 將任何超過約 25 個字的句子拆開。
- **標示轉折點。** 「轉向產品方面…」、「有兩件事需要你的注意…」。
- **以行動結束。** 重點回顧聆聽者應該做什麼，因為那是他們需要記住的內容，且他們無法向上捲動查看。
- **捨棄純視覺內容。** 表格、程式碼區塊和圖表應以一句話概括或省略，絕不要唸出來。

將這份口語稿寫入其專屬的 `.txt` 檔案。保留包含完整連結的原始書面版本 — 音訊是它的伴隨產物，而非替代品。使用者稍後會想要點擊連結。

## 合成

```bash
./scripts/tts.sh <input.txt> <output.mp3> [voice.safetensors]
```

該指令碼會去除任何殘留的 markdown，依據句子邊界將文字分割成約 600 個字元的區塊（長篇單一輸入的品質會下降），合成每個區塊，並將結果串接成 96kbps 的單聲道 MP3 — 檔案小到足以同步到手機，且品質足以供語音使用。

環境變數覆寫：

| 變數 | 用途 |
|---|---|
| `SPEAK_TTS_BIN` | 指向特定 `pocket-tts` 二進位檔的路徑；略過所有自動偵測。 |
| `SPEAK_TTS_HOME` | 建立/尋找快取 virtualenv 的位置。預設為 `~/.cache/speak-summary/venv`。 |

## 語音

預設的英文語音為 `alba`。若要使用不同的語音，`pocket-tts` 支援從簡短乾淨的音訊範例進行聲音複製 (voice cloning)：

```bash
pocket-tts export-voice --help
```

將產生的 `.safetensors` 檔案作為第三個引數傳遞給指令碼。

僅複製你擁有使用權限的聲音。未經明確同意，請勿複製真實人物的聲音 — 無論是同事、客戶還是公眾人物。

## 輸出

- 除非使用者另有說明，否則預設輸出至 `~/Music/Briefings/`；這樣很容易將手機或 podcast 應用程式指向該處。
- 將檔案命名為 `<subject>-<YYYY-MM-DD>.mp3`。
- 回報路徑、持續時間與檔案大小。
- 提議進行播放：在 macOS 上使用 `afplay <path>`，在其他地方使用 `ffplay -nodisp -autoexit <path>`。

## 長度指引

對於常規摘要，目標長度為 4–6 分鐘，以自然的語速來說大約是 600–900 個口語單字。若來源內容執行時間會超過約 10 分鐘，請主動說明並提供更精簡的編輯或拆分為多個檔案 — 對於資訊性音訊，超過這個長度專注力會急劇下降。

## 鏈結至其他技能

自然的模式是*收集 → 摘要 → 口述*：

- `roundup` → `speak-summary` — 現況簡報的口述版本。
- `daily-prep` → `speak-summary` — 明天的時程表，今晚先聽。
- `meeting-minutes` → `speak-summary` — 掌握你錯過的會議內容。

當作為鏈結的一部分被呼叫時，請勿重新摘要。上游技能負責「說什麼」；此技能負責「聽起來如何」。取得其輸出，為耳朵重寫，然後進行合成。

若要無人值守執行（在早餐前準備好簡報），可以使用工作流程排程上游技能，並讓它在結束時呼叫此技能。

## 疑難排解

**音訊在句子中途中斷。** 區塊超出了模型適應的長度。縮短口語稿中的句子。

**單字發音錯誤。** 在輸入中以注音/發音拼寫它們 — 例如將「Kubernetes」拼為「koo-ber-net-eez」。這是準備口語稿的正常環節。

**首次執行很慢。** 那是一次性的模型下載。之後的執行大約一秒內即可啟動。

**安裝後找不到 `pocket-tts`。** virtualenv 可能已過期，或者你的 `python3` 可能不在支援的 3.10–3.14 範圍內。刪除 `~/.cache/speak-summary/venv` 並重新執行，或將 `SPEAK_TTS_BIN` 指向已知的二進位檔案。
