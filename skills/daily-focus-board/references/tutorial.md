# 使用每日專注看板 (Using the Daily Focus Board)

一個溫暖、視覺化的一日看板，您可以**透過與您的 AI 夥伴 (Ember) 對話**來執行。您設定
任務；您透過對話與幾項一鍵控制項保持其最新狀態。本指南介紹如何在
**GitHub Copilot 應用程式**（最佳體驗）以及在任何地方**直接透過 Ember** 執行它。

## 快速入門

只需詢問：

> 「為我製作今天的專注看板。」

Ember 將詢問您的幾項任務（或從您已經說過的話中擷取），產生
看板，在本機提供服務並開啟它。就是這樣 — 您正在與夥伴一起開啟您的一天。

## 兩種執行方式

### A) 在 GitHub Copilot 應用程式中（瀏覽器畫布）— 推薦
該應用程式可以在聊天旁邊直接顯示**瀏覽器畫布 (browser canvas)**，因此看板就位於您的
對話旁。

1. 要求 Ember 製作看板。它為資料夾提供服務（例如 `python -m http.server 8790 --bind 127.0.0.1`）並給出
   `http://localhost:…/…html` URL。
2. 開啟指向該 URL 的**瀏覽器畫布**。看板位於側邊面板；聊天保留在左側。
3. 在工作時與 Ember 對話；點擊看板以進行快速更新。進度會自動儲存 (localStorage)。

### B) 直接透過 Ember（任何具有此技能的 Copilot 會話）
相同的流程，只是沒有側邊面板的精緻感：

1. 「為我製作今天的專注看板。」
2. Ember 為其提供服務並給出 URL — 在瀏覽器中開啟它。
3. 透過對話 + 點擊來驅動它。

> localStorage 需要 `http://` 來源，因此請一律為資料夾**提供服務**，而不是按兩下
> 該檔案。如果確實無法提供服務，檔案仍可開啟，但進度可能無法保存。

## 每日循環

**1. 抵達（早晨）。**
- **簽到：** 點擊*基準線之下 / 中間 / 之上* — 僅覺察您的抵達狀態，不做
  評判。（低於基準線？請保持溫和並縮小第一步。）
- **設定箴言：** 輸入今天的意圖，點擊 🔄 獲取建議，或向 Ember 索取一個。
- **列出約 4–9 項任務。** 保持為專注看板，而非待處理清單。標記單一真實**定錨**（賦予其
  `due` 時間）。選擇性設定每個任務的**優先級**（優先處理 / 排程 / 委派 / 稍後 — 點擊
  🧭 查看其含義）。

**2. 工作（白天期間）。**
- 點擊任務標籤將其移至**待辦 → 進行中 → 完成**（開始即算數 — 慶祝它）。
- **記錄動能筆記**（「初稿完成」）— 它們建立了您當天的故事。
- 當清單感覺過於繁雜時，**專注模式** (🎯) 會調暗除一項任務外的所有內容。
- 有分心的想法？**將其暫存**在 🧠 腦力傾倒盒中並繼續前進。
- 需要擷取新內容？直接在看板上 **➕ 新增任務**。
- 使用 **⠿** 控點依重要性重新排序，或點擊 **⬍ 依優先級排序**。
- 在行內重新命名任何方塊的**標籤**。

**3. 結束（一天結束時）。**
- 點擊 **💾 下載總結** 將當天保留為 Markdown 檔案，或 **📋 複製**它。
- 如果您複製了它，**將其貼給 Ember** — Ember 可以記錄您的一天日誌並協助您規劃明天。
- 使用 **⤳ 非今日** 順延未完成的事項 — 這是一個健康的選擇，而不是遺漏。

## 對 Ember 說的話

- 「我今天低於基準線 — 給我一個溫和的箴言和一個微小的第一步。」
- 「我接下來該做什麼？」→ Ember 指出**一件事**並可以開啟專注模式。
- 「在看板上新增『打電話給牙醫』。」
- 「幫我排定優先級 — 什麼是真正重要的，什麼只是緊急的？」
- 「這是我的一日結束總結：…」（貼上它）→「記錄此日誌並規劃明天。」

## 須知事項

- **它是您的且為可選項。** 每項功能都是一項支援，而非必要條件。對所有人
  專注友善；絕非診斷。
- **保持精簡。** 如果超過約 9 個進行中任務，看板會給予提示 — 將幾項順延至明天。
- **排程象限**（重要不緊急）是優秀、非慌亂工作所在之處 —
  為其保留時間。
- **狀態按瀏覽器區分。** 一日結束總結是您將一天*移出*瀏覽器的方式。
