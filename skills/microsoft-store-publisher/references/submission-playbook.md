# Microsoft Store 提交流程手冊

## 進入 Partner Center 之前

1. 完成產品行為與套件相關的整合。
2. 在支援的 Windows 版本與架構上測試應用程式。
3. 準備：
   - 隱私權政策
   - 支援 URL
   - 產品網站
   - 授權條款
   - 第三方聲明
   - 必要時的對應原始碼（corresponding-source）資訊
   - 真實的螢幕擷取畫面
   - 應用程式圖示
   - 認證（certification）說明
4. 辨識會影響政策或審查的功能：
   - 完整信任
   - 啟動工作
   - 背景行為
   - 本機網路存取
   - 帳戶
   - 個人資訊
   - 購買項目
   - 使用者產生或對外顯示的內容
   - 成人內容
   - 位置資訊
   - 生成式 AI

## 建立產品

1. 檢查候選名稱。
2. 預留最終名稱。
3. 記錄產品身分識別值。
4. 使用這些精確的值重新建構 MSIX。
5. 檢視套件。
6. 執行 WACK。

如果名稱使用其他公司的產品或通訊協定商標，請先停下，
並檢視該商標所有者的命名指引。在描述中優先使用相容性
措辭，而非將商標用於產品名稱。

## 定價與可取得性

決定並確認：

- 免費或付費。
- 市場。
- 是否公開發布且可被搜尋到。
- 發布時間。
- 認證完成後自動或手動發布。
- 相關的組織授權。

儲存定價或市場變更會影響商業可取得性。
如果使用者尚未指定，儲存前請先取得使用者
對精確設定的核准。

## 屬性

根據實際功能選擇類別。提供：

- 隱私權政策 URL
- 網站
- 支援 URL
- 個人資訊聲明
- 硬體與功能聲明

除非應用程式真正支援且已測試該功能，
否則不要選擇無障礙認證、可移除式儲存空間、OneDrive
備份、遊戲錄製、混合實境、手寫筆、購買項目或生成式 AI。

## 年齡分級

根據應用程式的行為作答，而非基於目標受眾。

顯示來自其他已配對裝置即時內容的應用程式，
即使沒有策劃內容目錄，也可能需要聲明其存取線上
內容。這不當然代表銷售者提供成人內容、
通訊、購買項目、獎勵、精確位置共享或不受限制的網頁瀏覽。

接受 IARC 條款是一項法律行為。
在接受前，立即取得使用者新的核准。

## 套件

1. 上傳最終的未簽章 Store MSIX。
2. 等待驗證。
3. 驗證：
   - 檔案名稱
   - 套件版本
   - 架構
   - 裝置類別
   - 最低作業系統版本
   - 驗證狀態
4. 解決每個阻塞性錯誤。
5. 說明每個受限制功能的警告。

如果 Partner Center 拒絕套件的顯示名稱，請檢視
`Package/Properties/DisplayName`。它必須與預留名稱完全相符。

## 提交選項

設定發布時機，並說明受限制的功能。

有用的完整信任說明應列出：

- 應用程式的桌面技術。
- 使用的原生 Windows API。
- 輔助程序架構。
- 啟動與通知區域整合。
- 是否使用權限提升、服務、驅動程式、全域系統設定
  與雲端服務。

使用 `templates/run-full-trust-rationale.md`。

## Store 商品列表

提供：

- 包含具體行為的產品的描述。
- 連線或設定步驟。
- 功能清單。
- 簡短標題。
- 開發者名稱。
- 搜尋關鍵字。
- 隱私權行為。
- 硬體與網路需求。
- 已知的限制，包含 DRM 或受保護內容。
- 適用的時候，附上商標所有權聲明與非關聯聲明。
- 授權與原始碼資訊。
- 解析度清晰可讀的真實螢幕擷取畫面。

不要捏造獎項、指標、顧客引言、相容性、
無障礙或安全性聲明。

## 額外測試資訊

撰寫讓 Microsoft 測試者可以不需猜測就能執行的說明：

- 所需的 Windows 版本與架構。
- 所需的實體硬體。
- 同一網路或防火牆需求。
- 精確的連線流程。
- 配對或 PIN 步驟。
- 預期的視窗、通知區域圖示、通知、音訊與全螢幕行為。
- 啟動行為。
- 輔助程序行為。
- 受保護內容的限制。
- 是否需要憑證。
- 測試失敗時如何找到日誌。

使用 `templates/certification-notes.md`。

## 最終提交

1. 重新載入概觀。
2. 確認每個區段都已完整。
3. 確認套件已驗證。
4. 確認 WACK 已通過。
5. 以單獨的核准處理已更新的協議。
6. 再次重新載入概觀。
7. 確認 **Submit for certification** 已啟用。
8. 告知使用者自動發布的後果。
9. 取得新的核准。
10. 只提交一次。
11. 確認 **In certification**。

## 提交之後

監視 Partner Center 與公開的 Store 頁面。認證可能包含：

- 前處理（pre-processing）
- 套件安全性檢查
- 技術合規
- 內容合規
- 受限制功能審查
- 發布

核准後，以匿名方式驗證公開 URL。如果遭拒絕，
在編輯下一次提交之前，先保留查得文字與任何報告附件。
