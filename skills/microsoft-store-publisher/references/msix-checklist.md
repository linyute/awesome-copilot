# MSIX 檢查清單

## 身分識別

- 在最終 Store 建構之前，先預留產品名稱。
- 從 Partner Center 複製套件身分識別名稱與發佈者 ID。
- 使用精確的發佈者字串，包含完整的 `CN=...` 值。
- 將 `Package/Properties/DisplayName` 設為精確的預留產品名稱。
- 應用程式的視覺顯示名稱與啟動工作顯示名稱
  必須與預留的產品名稱保持一致。
- 上傳 Store 時，請勿重複使用開發身分識別。

## 版本

- 使用四組數字組件。
- 第一組組件必須不為零。
- 每組組件都必須符合 MSIX 版本範圍。
- 上傳 Store 之前，第四組組件必須為 `0`。
- 每個取代套件的版本，都必須大於
  已與該產品關聯的版本。
- 保留應用程式可見版本與套件版本對應關係的文件。

## 封裝

- 只指定應用程式支援的裝置類別。
- 宣告正確的處理器架構。
- 設定合理的最低 Windows 版本。
- 對封裝式的傳統 Win32 應用程式，
  適用的時候使用 `packagedClassicApp` 與 `mediumIL`。
- 只宣告應用程式真正需要的功能。
- 在每個已宣告的路徑中包含有效的 Store 與應用程式圖示。
- 適用的時候，包含隱私權資訊、授權條款、第三方聲明，
  以及對應原始碼（corresponding-source）資訊。
- 封裝生產二進位檔案，而非除錯版本。
- 不要包含私人符號、憑證、測試資料、快取、日誌，
  或開發設定。

## 完整信任桌面應用程式

- 只有在必要時，才宣告 `rescap:Capability Name="runFullTrust"`。
- 說明需要完整信任的確切 Win32 功能。
- 為輔助執行檔與命令列模式撰寫文件。
- 非必要時避免要求權限提升。
- 使用者層級的行為就足夠時，避免使用服務、驅動程式
  或全域系統變更。
- 針對啟動行為，優先使用封裝的 `windows.startupTask`
  與 Windows StartupTask API，而非登錄啟動項目。
- 在真實的套件身分識別下測試啟動工作。

## 簽章

- 保留要提交到 Microsoft Store 的套件為未簽章狀態。
- 認證（certification）完成後，由 Microsoft 為套件簽章。
- 對在 Store 以外分發的套件進行簽章。
- 進行外部簽章時，憑證主題必須與
  清單中的發佈者完全相符。
- 上傳之前，檢視最終套件的簽章狀態。

## 驗證

- 使用 `makeappx.exe` 解開最終的 MSIX。
- 解析解開的 `AppxManifest.xml`。
- 驗證身分識別、發佈者、版本、架構、顯示名稱、目標
  裝置類別、執行檔、信任層級、功能與延伸功能。
- 將解開的執行檔 SHA-256 與套件輸入值比較。
- 記錄 MSIX 的 SHA-256。
- 以套件身分識別安裝並啟動。
- 測試啟動、通知區域、輔助程序、網路、更新與解除安裝
  行為。
- 執行 WACK 並閱讀產生的報告。

## 常見拒絕原因

- `Package/Properties/DisplayName` 與預留名稱不相符。
- 套件使用開發身分識別。
- 版本未大於現有的套件版本。
- Store 套件使用了錯誤的發佈者憑證簽章。
- 未說明受限制的功能。
- 商品列表聲稱了套件並未提供的行為。
- 認證說明省略了必要的硬體、網路
  或配對步驟。
- 隱私權聲明與實際的資料處理方式相衝突。
- 螢幕擷取畫面是模擬圖，而非真實的應用程式畫面。
