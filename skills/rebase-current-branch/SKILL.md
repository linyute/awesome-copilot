# 重訂目前分支的基底

透過將使用中分支的認可重播於其上游遠端最新預設分支的頂端來更新該分支。使用存放庫實際的預設分支，無論其名為 `main`、`master` 還是其他分支名稱。

## 工作流程

1. **在變更任何內容前先進行檢查。** 執行 `git status --porcelain=v1 --branch --untracked-files=all` 與 `git branch --show-current`。確認目前分支不是預設分支並記錄任何本機變更。若工作樹有變更，請停止並詢問使用者要認可、暫存（stash）還是以其他方式處理。請勿自動暫存。
2. **識別上游與預設分支。** 檢查 `git remote -v` 與 `git remote show <remote>`（或遠端的符號 `HEAD`）以確定此存放庫視為預設的分支。可用時偏好使用為目前分支設定的上游；否則使用 `origin`。不要假設 `main` 存在或名為 `master` 的分支為最新。若無法明確識別預設分支，請詢問使用者。
3. **擷取最新的預設分支。** 僅擷取已識別的遠端與預設分支，例如：

   ```sh
   git fetch <remote> <default-branch>
   ```

   在繼續之前確認擷取的遠端追蹤參照存在。
4. **重訂使用中分支的基底。** 告訴使用者哪個分支將重訂基底至哪個遠端追蹤分支，然後執行：

   ```sh
   git rebase <remote>/<default-branch>
   ```

5. **處理衝突而不遺棄工作成果。** 若重訂基底停止，說明哪些檔案衝突以及重訂基底已暫停。僅在預期的變更明確時才進行解決；否則詢問使用者。解決後，暫存（stage）已解決的檔案並執行 `git rebase --continue`。若使用者想要放棄操作，執行 `git rebase --abort`。切勿使用 `git reset --hard`、捨棄使用者變更或略過認可以強制完成。
6. **提供驗證掛鉤。** 在重訂基底成功後，檢查存放庫記載的驗證步驟與已設定的掛鉤（例如 pre-commit 掛鉤或程式碼檢查與測試指令碼）。詢問使用者是否希望在繼續之前執行這些檢查。若他們同意，執行適用的檢查並回報結果；請勿繞過或停用掛鉤。
7. **驗證結果。** 當重訂基底完成時，執行 `git status --porcelain=v1 --branch --untracked-files=all` 並總結成果，包括所使用的基底分支、驗證結果（若有執行）以及任何剩餘的變更。除非使用者另外要求，否則請勿推送、強制推送或修訂（amend）認可。

## 快速路徑

對於上游預設分支已知且乾淨的工作樹，核心操作為：

```sh
git fetch <remote> <default-branch>
git rebase <remote>/<default-branch>
```

將 `<default-branch>` 替換為偵測到的分支名稱（`main`、`master` 或其他已設定的預設名稱）。切勿字面執行佔位符號指令。

## 安全規則

- 保留使用者的目前分支與未認可的工作。
- 不要重訂預設分支本身的基底。
- 不要假設本機 `main` 或 `master` 是最新的；重訂基底至擷取的遠端追蹤分支。
- 不要將推送或強制推送作為此工作流程的一部分。
- 若重訂基底已在進行中，檢查其狀態並詢問要繼續還是中止；不要啟動另一個重訂基底。
