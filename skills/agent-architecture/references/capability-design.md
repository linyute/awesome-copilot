# 領域能力與技能結構 (Domain Capabilities and Skill Structure)

在設計領域實質內容或檢查現有代理人是否執行必要工作時閱讀。此處描述規格，而非技能安裝或應用程式實作。

## 1. 從需求到能力

能力是指具有領域輸出的可觀察工作：例如，準備可測試的假設或在當前政策下處理請求。單純的「分析」階段既無法解釋方法，也無法解釋輸出。

建立精簡圖表：`需求／情境 → 能力 → 輸入與來源 → 方法／規則 → 輸出 → 檢查 → 執行者`。涵蓋主要情境，而非為每個技術動作都建立獨立資料列。

依意義配置職責：

| 機制 | 配置給它 |
|---|---|
| 模型 | 具備已定義依據、邊界與品質條件的解讀與綜合彙整 |
| 技能／領域指示 | 可重複的方法、範例、決策條件與來源處理 |
| 工具 | 具備合約的具體讀取、計算或外部動作 |
| 執行階段／一般程式碼 | 權限、結構描述、計算、狀態、限制與強制檢查 |
| 人工 | 需要其授權或領域判斷的決策與評估 |

一項能力可能會使用數種機制。技能不是子代理人、工作流程階段或 API 方法。可重複使用的方法、其專屬情境或獨立生命週期皆可證明建立獨立技能的合理性。單純的一次性轉換僅需單一設計內的指示與範例；能力圖不需要技能目錄。

## 2. 選定技能的規格

為每個所需技能填入包含任務專屬細節的欄位。將共用規則集中放置並連結至該處。方法複雜度決定深度，而非檔案數量。

| 欄位 | 內容 |
|---|---|
| 目的與選取 | 解決的需求；觸發條件與不適用案例；誰選取程序 |
| 輸入與情境 | 所需資料、權威來源、版本、存取權限、新鮮度；缺失或衝突時的行為 |
| 方法 | 領域步驟、選取條件與替代方案；結論的依據與不確定性邊界 |
| 輸出 | 產物欄位及其意義、消費者；一個簡短且填入資料的範例 |
| 工具與控制 | 所需操作；程式化檢查對比人工判斷；連結至共用授權合約 |
| 錯誤與停止 | 失敗、資料不足、允許的重做與使用者成果；連結至共用預算 |
| 驗證 | 一般、負向或困難範例；實用性條件與不可接受的結果 |
| 擁有權與變更 | 方法負責人、版本、更新／復原規則；適用時的使用者／租戶範圍 |

以具體操作方法取代「好好分析並妥善完成」。提出具備依據與狀態的未知領域規則，或識別具體缺口與負責人；切勿捏造企業政策。架構包含提議的程序，而非「稍後撰寫技能」的承諾。

## 3. 指示、材料與現有平台

顯示未來解決方案的邏輯結構：共用行為／授權合約 → 技能選取條件 → 領域程序 → 參考資料、範例與範本。針對每個元素，識別目的、消費者與載入條件。單一文件的各章節、檔案樹或儲存庫記錄皆可接受；空白目錄與重複指示不會增加實質內容。

情境一開始僅包含選取工作所需的最少共用規則與資訊；選定的程序僅接收所需材料。定義來源優先順序與企業規則的範圍。不受信任的資料與技能內容無法擴充執行階段權限。

針對選定的平台進行配置：`職責 → 現有機制與佐證 → 所需設定／新增項目 → 未驗證部分與驗證方法`。平台名稱既無法證明支援某項功能，也無法證明設定正確。若文件／版本不可用，提出所需合約而不要宣稱其已存在。

若存在共享與企業目錄，定義版本選取與覆寫規則、經授權的編輯者、衝突解決以及工具相容性。執行會記錄選定的版本。目錄更新不會在任務進行中無聲替換方法：定義在先前版本上繼續執行或明確遷移；針對已撤銷的版本或權限，描述安全停止與後續調查。

## 4. 填入資料的範例而非階段清單

以下範例為合成案例，用以說明描述深度，並非強加行銷於每個代理人。

**能力：** 準備啟用改進假設。輸入：簡報 B1 將啟用定義為建立的第一個工作區；報告 A7 指出部分新使用者在邀請同事步驟停止。報告中未包含放棄原因。

**方法：** 將觀察與解釋分開 → 形成可能原因 → 選擇能改變該障礙的干預措施 → 將其連結至可衡量的行為 → 識別何者能證偽該解釋。程序讀取 B1 定義與 A7 資料；模型提出因果假設，而工具提供報告存取與計算。

**輸出 H1：** 觀察——在邀請步驟停止 (A7)；提議原因——邀請過早要求同事參與（未證實）；干預措施——允許略過邀請；預期行為——第一個工作區建立；限制——無因果佐證，仍需要比較計畫。H1 的消費者是實驗設計者，而非發布工具。

**驗證與繼續：** 驗證事件定義與參照；產品負責人評估假設依據。設計實驗的比較方法、資料需求與決策規則。若 A7 僅包含頁面瀏覽量，將 H1 的初步觀察標記為未證實：使用者收到解釋與所需資料，而非宣稱障礙已確立或已達成成長。

針對您的專案，使用類似填入資料的中間產物詳細演練整個主要情境，並展示最終使用者成果。這是模擬演練，而非已完成實驗的佐證。完成套件的條件請參閱 [architecture-contract.md](architecture-contract.md)。
