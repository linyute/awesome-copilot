# 長時間執行任務：狀態、復原與資源 (Long-Running Tasks: State, Recovery, and Resources)

在處理長時間執行、背景、跨工作階段工作、暫停與復原時閱讀；在審查中，當宣稱具備此類保證時閱讀。預算與排程器小節亦適用於競爭的工作階段。第 1–4 節涵蓋檢查點、交接、恢復執行與測試；第 5–9 節涵蓋儲存庫、監督者／RTO／RPO、預算／斷路器、非同步決策與排程。沒有持久化狀態的一次性回答不需要此迴圈。下方的檔案名稱為範例，非強制性的後端或作業系統。

## 1. 檢查點政策

定義 `儲存內容 → 單一事實來源／寫入者 → 觸發條件 → 持久化寫入時序 → 一致性 → 允許的進度遺失 → 復原／失敗 → 檢查`。

將定期時間／步驟檢查點與重大事件結合：階段完成、已接受決策、人工等候、工作者交接。按允許的工作遺失與儲存成本選擇間隔；固定的 N/M 數值與情境窗口百分比並非通用的。非同步、結束時與繼續執行前的寫入提供不同的保證。若儲存庫不可用，指定該特定操作是否可繼續。

檢查點會連結目標及其版本、任務／依賴項、已接受決策、方法／輸入版本、產物／佐證連結、花費與未結預算保留、操作資訊以及下一個允許的步驟。授權與外部副作用狀態保留在受信任的執行階段／擁有系統中，而非壓縮摘要中。

多個檔案或資料表不會自動形成一致的快照。選擇交易、具版本資訊的清單／認可標記或原生檢查點工具保證。讀取者檢查快照識別碼與完整性；部分儲存的集合無法宣告階段完成。傳回先前的完整快照並不能復原後續的外部副作用：請先對帳操作日誌與預算。針對並行工作者，定義寫入負責人以及防止過期寫入者的保護機制。

## 2. 工作階段交接通訊協定

交接必須讓下一個工作階段無需閱讀整個對話或重複進行一般訪談即可繼續。

| 功能 | 充分內容 | 範例表示方式 |
|---|---|---|
| 環境還原 | 相依性／設定版本、經授權的準備、工具／資料可用性檢查 | init.sh、PowerShell、映像檔或原生開機程式 |
| 人類可讀進度 | 目標、已接受決策與理由、已完成工作、阻礙／未知項、下一步 | progress.md 或資料庫記錄檢視表 |
| 機器可讀任務 | 穩定 ID、依賴項、狀態、完成條件、結果與相關操作連結 | feature-list.json、tasks 資料表、原生圖形狀態 |
| 驗證套件 | 指向輸出、檢查、副作用與決策的具版本資訊指標 | [validation-loop.md](validation-loop.md) 下的 Evidence Bundle 清單 |

切勿在獨立且不一致的複本中重複權威狀態：人類檢視表可衍生自相同的記錄。該套件不儲存機密資訊；開機程式透過經授權的環境取得機密，且不賦予新權利。可定址檔案、實際載入的情境以及正確的繼續執行是可分別驗證的狀態。

## 3. 恢復執行

1. 檢查快照完整性、使用者／租戶擁有權以及當前目標：取消、任務變更或代理人停用可能在檢查點之後發生。
2. 還原相容的環境、方法與資料版本，或套用明確授權的遷移；切勿無聲替換方法。檢查所需情境的可用性／新鮮度。
3. 對照權威狀態對帳未完成與模稜兩可的操作。穩定的操作 ID 僅在已知下游去重／對帳合約時才有幫助。針對未知成果，保留不確定性，選擇允許的對帳或呈報，切勿盲目重複副作用。
4. 還原總花費／保留預算與期限。新工作階段或工作者不會重設限制。
5. 在下一個副作用之前，重新檢查確切動作、當前權利、核准與代理人生命週期。完成允許的步驟並將新檢查點連結至佐證。

### 填入資料的轉換與失敗

合成檢查點 C7：目標 H1、輸入 S3、方法 v2、報告 R4 為草稿、下一個任務 Q5 檢查數字；在 5 美元預算中，已花費 2 美元且已保留 0.50 美元。新工作階段讀取 C7，驗證 S3 新鮮度與任務狀態，取得可用佐證，並繼續 Q5，將 2.50 美元計為已認可預算。它不會再次詢問目標，也不會在 Q5 之前宣告已驗證的結果。

失敗案例：在獲授權的發布 op7 之後，回應遺失；已為 C8 儲存進度，但任務清單停留在 C7。此集合未確認完成。復原使用最新的一致快照加上 op7 日誌；讀回可確立發布並將其收據連結至結果。若對帳不可用，狀態為「副作用未知」，且不會自動允許重新發布。過期的核准不會阻止對已啟動動作的授權對帳，但不會授權新寫入。

## 4. 延續性測試

針對實質轉換，設計或安全執行在持久化記錄之前／之後、已傳送副作用之後以及部分快照期間的停止操作。僅使用指定的復原機制啟動新工作階段。檢查目標、限制、方法、版本、剩餘任務／預算的保留情況；不存在重複副作用與過期權限；正確的下一步與可理解的使用者狀態。

[evaluation-design.md](evaluation-design.md) 中的長跨度矩陣區分了累積歷程記錄、壓縮、交接與當機／恢復執行。測試設計不是已執行的執行階段檢查。本機下游測試資料並不能證明真實外部 API 的保證。

## 5. 基於生命週期的儲存庫

針對大資料量或長期保留，比較單一持久化後端與邏輯層級：熱（hot）——低延遲作用中狀態；溫（warm）——近期完成／暫停的任務；冷（cold）——根據成本與適用規則進行歸檔。三個層級並非強制要求；沒有儲存需求的任務則不需要。儲存層級不是信任層級，壓縮的模型情境也不能取代主要產物。

定義 `物件／單一事實來源 → 層級 → 轉換事件／時間 → 負責人 → 存取／保留 → 擷取延遲／成本 → 檢查`。自動遷移使用穩定 ID／版本與可驗證清單：複製並驗證完整性 → 原子的切換位址 → 依政策移除先前複本。遷移期間的讀取不得混合版本；失敗時保留最新完好的可用版本。歸檔還原（補水）具有等候狀態、逾時以及遺失／損毀物件成果。對代理人的透明性意味著保留讀取合約與識別碼，而非承諾即時存取。

ACL／租戶、加密／金鑰管理、刪除期限與適用的刪除保留適用於所有層級、複本與快取。歸檔／備份還原絕不能恢復已撤銷的權利或已刪除的資料；指定當前政策與刪除記錄的檢查。切勿匯入通用的法律保留期限。補水成本／時間計入預算與復原；達到所需 RTO 的最小套件可保留在快速儲存庫中，同時將其他產物歸檔。

## 6. 監督者與復原目標

針對自動繼續執行，將失敗偵測／復原擁有權指派給現有執行階段／協調機制或提議的監督者邏輯。獨立處理程序或 LLM 並非強制要求。合約：失敗／租約過期訊號 → 透過隔離（fencing）取得復原擁有權 → 已驗證檢查點與操作日誌 → 依第 3 節復原 → 健康驗證 → 重新排隊或停止。延遲的工作者絕不能重新獲得擁有權。即使隔離功能正常，已發起的外部副作用仍需要個別對帳。

將 RTO 定義為從明確選擇的失敗事件到安全恢復有用工作的目標時間；RPO 定義為特定狀態／進度類別的允許遺失。將目標與測量值分開。識別失敗網域（工作者、儲存庫、區域）、偵測、復原佇列、開機、補水、對帳與驗證：快速處理程序重新啟動並不能證明 RTO。若無持久化寫入／複寫時序，單靠檢查點間隔不能證明 RPO。授權、副作用與成本日誌可能需要比中間綜合彙整更強的持久性。

自動重新啟動具備嘗試與總時間限制、輪詢後退（backoff）、錯誤分類以及預算耗盡成果。損毀／不相容狀態、缺失當前權利與未知副作用無法透過無止境的重新啟動來解決。描述監督者／相依性失敗與負責人交接；復原不會繞過准入或獲得全新預算。

需求衝突範例：冷讀取耗時 40 分鐘，目標 RTO 為 10 分鐘，每 15 分鐘一次檢查點伴隨 3 分鐘的進度 RPO。當前設計無法證實這些目標。選項：快速復原套件、更頻繁的持久化記錄／日誌記錄，或經商定的目標變更；成本與測量決定選擇。在所述範圍內設計真實的冷恢復與工作者／儲存庫遺失測試；測量遺失的進度與達到安全有用步驟的時間。思想計算僅暴露了衝突。

## 7. 預算與斷路器

在 [architecture-contract.md](architecture-contract.md) 的一般限制合約下，連結 `task`（整體指派）、`session/run`（嘗試／互動區段）與 `horizon`（每個窗口的累積租戶／使用者配額）。指定貨幣／資源、帳本負責人、窗口邊界／類型、計費時間、已花費／已保留、不可部分完成准入、保留釋放與耗盡成果。層級為巢狀結構，而非累加為額外的可用預算：呼叫需通過所有適用限制。交接／重新啟動／新的一天不會重設任務限制；延遲成本與窗口邊界操作在明確政策下計數一次。委派者、重試、審查／守護者、復原與擷取計入相應成本。為實際負載套用儲存／CPU／網路配額。

範例：任務限制 8 美元，已花費 5 美元，已保留 1 美元；租戶每日限制 60 美元，已花費 58 美元，已保留 1 美元。任務剩餘 2 美元，租戶剩餘 1 美元。兩個工作者無法各自從相同剩餘中獨立保留 1 美元；工作階段剩餘既不擴充父層限制。花費未知的保留不會僅因逾時就釋放。在換日邊界，保留／扣款窗口政策必須同時保留兩項限制且無重複計算。

區分預算耗盡、缺乏進展以及針對效能劣化相依性的斷路器。針對斷路器定義訊號／錯誤延遲窗口、範圍（工具／提供者／租戶）、關閉／開啟／半開啟轉換、冷卻時間、有界限的復原探測與關閉條件。在沒有一般授權與安全重試合約的情況下，自動外部寫入探測是不可允許的；讀取／健康探測不能證明寫入路徑健康。「開啟」會暫停受影響操作、記錄進度，並顯示原因／下一步；未受影響的獲授權動作可繼續執行。模型切換／後備需要相容的權利、資料政策、品質檢查與總預算。強制檢查不得因效能劣化而停用。

## 8. 非同步人工參與

使用 [design.md](design.md) 的決策圖：針對背景任務定義在權限範圍內的負責人／備用接收者、管道／可用性窗口、決策期限、無重複提醒、取消、逾時與可見等候狀態。卡片包含目標、確切有限的版本／動作集合、變更、依據、風險與決策選項；摘要有助於審查，但不能取代對實質佐證的存取。批次核准會約束每個動作／版本；排除或變更的項目不繼承權限。執行前需套用第 3 節的重新檢查。

切勿讓運算工作者等候人員。保存狀態並在決策事件時恢復執行，防止重複交付與過期。沉默不是同意。到達期限時：部分輸出、重新排程／取消或獲授權的呈報；人員可用性並不能保證滿足期限。依據 [evaluation-design.md](evaluation-design.md) 測量佇列／勞力。互動式釐清與背景佇列可共用單一 UI，但具有明確相異的期限／狀態。守護者是基於風險的，非強制性；在任務持續時間與累積情境下測試它，並將成本計入總上限。

## 9. 排程器與競爭任務

針對多個任務／租戶，定義准入／執行政策：互動／背景類別、業務關鍵度與指派來源、期限／寬限時間（slack）、配額／並行性、估計成本／持續時間、先佔可允許性、決勝條件與防止匱乏保護。模型不得自行提高優先級。互動性是一項政策因素，而非對關鍵背景工作的無條件優先權。依負載選擇 FIFO、個別佇列、加權公平或保留容量；獨立服務並非必要。

定義有界限的佇列／背壓、任務負責人租約／隔離、共享預算、安全暫停點與取消後果。在安全的檢查點邊界進行先佔；已發送的操作不視為已取消。預測的期限／預算違規會觸發具體決策：推遲／拒絕、在已商定政策下縮減輸出或呈報。切勿在沒有容量的情況下承諾完成，或從緊急性衍生授權。

測試混合負載：互動湧浪、接近期限的關鍵背景任務、嘈雜租戶、長時間不可分割操作、重複交付以及工作者遺失。在保留限制的同時，測量佇列／年齡、按類別劃分的等候／完成、錯失期限、匱乏、有用進展與成本。單純佇列或優先級設定並不能證明其中任何一項。沒有競爭的一次性助理可能不需要排程器。
