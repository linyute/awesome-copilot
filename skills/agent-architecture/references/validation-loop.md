# 驗證迴圈與完成佐證 (Validation Loop and Completion Evidence)

在設計驗收、發行與回饋，或診斷未確認成果時閱讀。這些是單一架構的功能，非強制性的獨立服務。簡單任務需要對適用檢查進行精簡描述；請解釋不適用性，而非建立空白章節。檢查集合不會擴大訪談範圍，也不會取代領域方法。

## 1. 功能圖

針對每項適用功能，填入 `輸入／版本 → 檢查屬性 → 機制與負責人 → 執行時序 → 通過／失敗／未知 → 後果 → 佐證`。顯示平台提供何物、提議何物以及何者未知。「不適用」不同於缺失強制檢查。

| 功能 | 架構決策 | 診斷檢查 |
|---|---|---|
| 評估登錄檔 (Eval Registry) | 情境版本、oracle／量表／評分器、執行條件、閾值／准入條件。能力、回歸、呈報；工作長時間執行時的長跨度 | 實際執行／評估的情境對比排除的情境；版本／分母是否具可比性 |
| 審查 (Review) | 誰檢查領域含義、架構或產物品質：程式、模型、人工或其組合。任務專屬檢查清單與補救界限 | 檢查器能否區分良好與看似合理的錯誤結果，且是否具備足夠的主要資料 |
| 安全閘門 (Security Gate) | 適用的基於資產的威脅／檢查。針對程式碼：依風險進行 SAST/DAST、機密／依賴項檢查；針對文字：資料保護與輸出准入 | 是否涵蓋真實路徑，危險副作用／外洩是否可能在檢查前發生 |
| 政策閘門 (Policy Gate) | 檢查具體動作、委託人／租戶、資源、參數、權限、額外條件；強制執行點 | 參數替換、核准過期／撤銷、替代處理常式、重試／恢復執行；負向裁決是否確實阻止動作 |
| 佐證組合包閘門 (Evidence Bundle Gate) | 所宣稱成果佐證的完整性、相關性與新鮮度 | 所有欄位皆存在但測試參照舊版本；副作用未知；連結無法存取或不支援主張 |
| 發行閘門 (Release Gate) | 准入複合版本進入作用中狀態：負責人／政策、檢查、有界限試點、停止／復原 | 未驗證版本是否能啟用；設定／資料／持續任務狀態一致性 |
| 遙測回饋 (Telemetry Feedback) | 維運訊號 → 診斷案例 → 評估／需求 → 針對性變更 → 比較 → 接受／復原 | 失敗是否可重現、結果在調校之外是否有改善，且未為了全綠分數而變更條件 |

順序取決於副作用：寫入准入在寫入前檢查；結果確認在寫入後檢查。圖表並未規定在每個步驟皆需循序執行所有七個元件。登錄檔可以是具版本資訊的測試目錄；審查可以是現有檢查或人工；本機助理的發行可以是受控的版本替換。平台文件並不能證明設定或涵蓋範圍。

若無強制裁決，結果不得准入。選擇具體成果：等候、停止或允許的降級。評估器失敗並不能證明領域結果錯誤。軸向、測量失敗以及正向／負向控制請參閱 [evaluation-design.md](evaluation-design.md) 與 [diagnostic-review.md](diagnostic-review.md)。

## 2. 佐證組合包 (Evidence Bundle)

設計一個連結權威記錄的驗證套件或清單。依環境選擇格式；獨立服務並非必要。針對實質條件，連結：

`任務／執行 ID → R/E-ID → 複合代理人與實質輸入版本 → 輸出 ID／版本 → 檢查／評分器與裁決 → 佐證連結 → 完成狀態／未知`。

針對動作，加入操作識別碼、確切參數／負載版本、適用授權／政策決策以及確認的副作用狀態。針對維運，加入包含會計涵蓋範圍的成本以及指向後續使用者價值測量的連結。複合版本包含模型、提示／技能、工具、政策、執行階段與實質資料。明確標記待決數值。

檢查：

- 佐證屬於所需版本、情境與資料範圍；PDF 建置日期不能證明這點；
- 經授權的審查者可成功解析連結且內容支援結論；雜湊能證明身分，而非正確性；
- 必要檢查確實已執行；規劃／略過／錯誤／未知不得變成通過；
- 實際副作用與已發送請求及意圖保持分開；逾時在對帳前保留不確定性；
- 套件完整性、結果正確性、動作權限與展現出的效益具有獨立狀態；
- 未包含機密或不必要的敏感資料；存取、保留與刪除遵循適用規則，而非通用的永久原始日誌記錄。

模型不得透過撰寫 `done=true` 為自己賦予最終准入。針對提議的代理人，組合包指定未來的佐證與填入資料的合成範例，而非真實執行結果。[result-delivery.md](result-delivery.md) 下的最終 PDF 呈現發現與佐證連結，但不能取代佐證。

### 範例：實驗報告

合成 `run r18`：需求 E4——時期 P 的正確報告；輸入 `snapshot S3`，方法 v2，輸出 `report R4`。數值檢查將 R4 與 S3 進行比較；領域審查檢查因果推論限制。MAU 從 1000 變為 1100；無隨機分組，且價格也發生變動。+10% 的計算可能通過，但實驗的貢獻仍未證實。下一個實驗決策取決於限制，而非捏造的因果效應。

若 R4 被 R5 取代，成功的 R4 檢查不准入 R5。若 R5 發布逾時，最終狀態為「報告已準備；發布未確認」，並附帶操作 ID 與下一個經授權的對帳步驟。若發布從未獲得授權，請另外記錄原因。

## 3. 檢查元件亦具備合約

若規劃了守護者／審查代理人 (Guardian/Review-Agent)，請區分 `觀察 / 事前攔截 / 修正`。針對每種模式，定義可見資料、干預點、權限、逾時、不可用時的行為、成本及其專屬的假性接受／假性阻礙檢查。修正是受一般准入規則約束的個別動作；審查者權限不會自動擴充。

範例：寫入在 t15 完成；Guardian 在 t20 傳回拒絕。監視器偵測到了事件，但事前禁止寫入並未被強制執行。若要驗證修正，請透過實際分派器／配接器傳送禁止與允許的操作：前者絕不能產生外部副作用；後者產生副作用並獲得確認。請另外測試 Guardian 不可用的情況。模型評審無法取代強制授權，亦無法保證不存在攻擊。

審查受商定輪次、時間／成本與停止規則界定。未解決的分歧會變成具體的待決決策或呈報，而非工作者與審查者之間無休止的交流。切勿為了速度或診斷實驗而停用強制控制。
