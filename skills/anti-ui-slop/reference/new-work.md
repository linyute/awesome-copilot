# 全新介面或重大重新設計

從產品出發，而非從風格潮流出發。在選擇方向之前，請先研讀需求簡介、現有元件、內容、各項限制以及任何目前的介面。

## 決定介面

- 識別主要使用者、其核心任務，以及在此介面中最重要的一個動作。
- 選擇一個符合產品特性的連貫視覺方向。不要提供風格選單，也不要為了追求新穎而製造新穎。
- 建立清晰的閱讀順序：方向定位、主要內容、主要動作，然後是次要詳細資訊。
- 若有既有的設計系統，請重複使用它。僅在所要求的任務真正需要新項目時才進行擴充。
- 保持熟悉的控制項符合習慣。獨特性應來自產品的內容、結構、排版、圖像與互動 — 而不是將標準控制項改得怪異。

## 建構完整狀態

- 使用真實內容或明確標記的預留位置內容來檢驗版面配置。
- 納入任務所需的狀態：載入中、空白、錯誤、成功、停用，或實際可能發生的復原狀態。
- 在結構上定義響應式行為。決定哪些元素堆疊、收合、捲動或保持固定，而不僅僅是縮小桌面版面配置。
- 保持排版、間距、色彩、圓角半徑、圖示樣式與動態效果的內部一致性。
- 僅在解釋轉場、揭露狀態或提供回饋時才使用動態效果。

## 驗證一次

在環境支援時，以相關尺寸渲染結果。修復可觀察到的裁切、重疊、失真媒體、無法存取的控制項、中斷的焦點、難以閱讀的階層架構或無回應的互動。當所要求的介面運作正常且感覺連貫時即可停止；不要在工作周圍增添額外的形式儀式。
