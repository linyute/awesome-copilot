# 建構 Agent Skill Stack (Build an Agent Skill Stack)

為使用者的實際成果建構最小可用的堆疊。切勿將特定領域範例或固定生命週期強加於不同的請求上。

## 1. 選擇面向使用者的深度

預設為**純文字/白話模式**。假定使用者不需要理解路徑、修訂版本、雜湊值、資訊清單、靜態分析或執行階段細節。

在白話模式下，顯示：

- 使用者嘗試完成的目標；
- 以日常語言表達的步驟；
- 目前已具備哪些功能；
- 哪些 Skills 是推薦、可選、重疊或不合適的；
- 每個候選項目的被廣泛使用程度；
- 是否通過安裝安全檢查與安全試跑；
- 可能需要哪些帳戶存取權限或外部操作。

將原始路徑、修訂版本、檔案指紋、原始分數、稽核證據和相依性細節保留在內部記錄中。僅在使用者詢問技術細節或知情同意需要特定技術事實時才顯示它們。

## 2. 動態推導工作流程

閱讀 [references/workflow-model.md](references/workflow-model.md)。從使用者想要的最終結果開始，而不是請求中的領域字詞。

僅提出其答案會實質改變結果、存取邊界、成本或堆疊的問題。從成功目標向後推導工作流程，然後從可用的起點向前驗證。

請勿重複使用先前的編號流程。不要假設每個請求都需要研究、內容建立、發佈、分析、儲存或自動化。僅在使用者成果需要時才新增步驟。

當一個步驟具備一個可理解的操作、一個主要結果、一個存取邊界和一個可觀察的成功條件時，停止分解。保留內部技術能力卡片；向使用者展示簡短的白話流程。

## 3. 優先搜尋本機索引

閱讀 [references/local-index-and-profiles.md](references/local-index-and-profiles.md)。

若存在目前的本機 Skill 索引，請在搜尋檔案系統或網際網路之前先搜尋它。若遺失或過期，請從相關的 Skill 根目錄重新建構：

```bash
python3 scripts/skill_index.py build \
  --root ~/.codex/skills \
  --root ~/.codex/plugins/cache \
  --root .codex/skills \
  --root ~/.agents/skills \
  --root ~/.hermes/skills \
  --output ~/.codex/skill-index.json
```

該索引儲存名稱、摘要、別名、範圍、能力術語、更新時間和內部檔案指紋。它絕不執行 Skill，也不儲存任何使用歷史記錄。

若目前專案具有 `.codex/skill-stack.json`，請將其作用中 Skills 和路由規則視為首選堆疊。僅在遇到未涵蓋的功能或使用者要求替代方案時才在設定檔之外搜尋。將來自不同本機根目錄的同名項目視為審查項目；請勿靜默合併它們。

## 4. 繪製能力圖譜，包含間接輔助工具

對於每個必要步驟，內部記錄：

- 所需的輸入、操作和輸出；
- 限制條件、頻率和規模；
- 本機/讀取外部/寫入外部邊界；
- 帳戶、權限和核准需求；
- 成功條件和備用方案；
- 前置步驟與後續步驟。

然後僅在相關時考慮跨領域需求：品質/風格、準確性、合規性、隱私性、在地化、資料品質、編排和可觀測性。

透過 `輸入 -> 操作 -> 輸出` 匹配 Skills，而不是透過標題相似性。這允許 Humanizer 匹配自然寫作需求，即使使用者的領域從未出現在其名稱中。

不要強制每個步驟對應一個 Skill。一個 Skill 可能涵蓋多個步驟；一個步驟可能需要工具、MCP、連接器或一般代理功能，而非另一個 Skill。

## 5. 透過四個維度進行搜尋

閱讀 [references/discovery-ranking.md](references/discovery-ranking.md)。透過以下維度搜尋每個未涵蓋的功能：

1. **直接需求**：使用者的領域與操作。
2. **底層操作**：實際的轉換或資料任務。
3. **支援成果**：品質、安全、風格、合規性、評估與監控。
4. **連線方法**：CLI、MCP、API、連接器、瀏覽器自動化、儲存與交接。

擴展中/英文別名、動詞、名詞、輸出與相鄰術語。在可能的情況下搜尋標題、說明、標題與完整 `SKILL.md` 內容。

使用多個來源，因為沒有任何註冊表是完整的：

- 本機 Skill 索引和已安裝清單；
- GitHub 連接器或 GitHub 檔案/存放庫搜尋；
- `npx skills find <query>` 與 skills.sh；
- agentskill.sh 或其他可用的註冊表；
- OpenCLI 用於廣泛的 Web 探索與平台特定研究。

循序執行由瀏覽器支援的 OpenCLI 搜尋。未經使用者核准，請勿登入、新增憑證或啟用連接器。

## 6. 驗證並評估候選項目

將每個搜尋命中視為候選項目，而非推薦。識別規範存放庫與確切的 Skill 路徑。閱讀完整的 Skill 以及安裝將使其可存取的每個可執行檔案。

在下列情況下拒絕或隔離候選項目：

- 其來源或聲稱的能力無法驗證；
- 其結構無法安裝；
- 必要相依性不相容或不可用；
- 關鍵憑證存取、資料上傳、提示注入、破壞性操作或混淆程式碼仍未解釋；
- 其唯一可能的測試將發佈、發送、購買、刪除或更改真實帳戶；
- 授權條款或平台條款使得預期用途具有實質不確定性。

使用 [references/discovery-ranking.md](references/discovery-ranking.md) 中的評分標準對通過這些關卡的候選項目進行排名。實際採用率與社群證據佔分數的 25%。保留未知值為未知。

偏好滿足所有必要成功條件的最小堆疊。將候選項目分類為：

- **必要 (Required)**：完成成果所需。
- **有幫助 (Helpful)**：提升品質、安全性或效率。
- **替代方案 (Alternative)**：互斥的替代品。
- **不建議 (Not recommended)**：被封鎖、多餘、不相容或過於不確定。

## 7. 分析衝突與範圍

閱讀 [references/security-installation.md](references/security-installation.md)。檢查身分、啟動、指令、資源、相依性、資料格式、權限與合規性衝突。

透過選擇一個主要 Skill、定義與輔助工具的狹窄交接、保持替代方案互斥或不安裝多餘候選項目來解決重疊。

偏好針對特定任務功能的專案本機 Skills 與專案 Skill Stack Profile。僅針對應廣泛提供的功能使用全域安裝。

## 8. 以白話語言呈現建議

預設輸出：

1. **您想要實現的目標**：簡短重述。
2. **工作如何拆解**：為此請求推導出的簡短編號流程。
3. **您已具備的項目**：現有可用 Skills 與未涵蓋的缺口。
4. **建議組合**：必要、有幫助、替代方案與不建議。
5. **為何選擇這些**：以日常語言說明的符合度、採用率、安全檢查、安全試跑與衝突。
6. **需要您決定的事項**：帳戶存取權限、付費服務、外部發佈或安裝選擇。

使用標籤如 `已具備`、`推薦`、`可選`、`不建議`、`安全檢查通過`、`安全試跑通過` 與 `最近確認可用`。請勿在預設回應中顯示雜湊值或本機路徑。

在有用時提供 `查看技術詳情`。技術檢視可包含規範來源、修訂版本、檔案指紋、確切目的地、原始證據、相依性、權限與復原細節。

當使用者需要可重複使用的成果時，從結構化 JSON 建立可分享的建議卡片：

```bash
python3 scripts/render_stack_card.py \
  --input /path/to/stack-card.json \
  --output /path/to/stack-card.svg
```

保持卡片在沒有技術路徑或原始雜湊值的情況下易於理解。包含目標、選取的 Skills、各角色與狀態、安全邊界與驗證日期。

## 9. 僅在同意後安裝

推薦不等於授權安裝。在使用者選擇後遵循 [references/security-installation.md](references/security-installation.md)。

預設為分階段安裝。僅在每個選取的 Skill 通過嚴格關卡、具備確切釘選身分、無未解決衝突、不會覆寫現有目的地且使用者明確核准批次時，才允許一鍵批次處理。

對於已下載並檢查過的 Skill 目錄，先進行預覽：

```bash
python3 scripts/stage_install.py \
  --source /path/to/skill-a \
  --dest ~/.codex/skills \
  --manifest ./skill-stack-lock.json
```

僅在核准後帶有 `--apply` 重複執行。切勿靜默新增憑證、接受新權限、覆寫已安裝的 Skill 或發佈/發送/刪除外部資料。

在使用者選取堆疊後，提供在模擬模式 (dry-run) 下建立專案設定檔：

```bash
python3 scripts/project_profile.py \
  --project /path/to/project \
  --name project-stack \
  --skill skill-a \
  --skill skill-b
```

僅在使用者確認設定檔後使用 `--apply`。

## 10. 執行召回檢查

在安裝或設定檔變更後，執行**召回檢查 (recall check)**，而非效能基準測試：

1. 命名任務的直接請求；
2. 使用不同字詞的自然改述；
3. 應該引入輔助工具（例如寫作品質、事實查核或合規性）的支援性請求。

確認選取了正確的主要與支援 Skills，且無關的 Skills 保持排除。回報簡單結果，例如 `3/3 種說法都能正確識別`；將原始提示與路由細節保留在技術檢視中。

請勿收集或儲存使用者提示記錄、命中/未命中日誌或路由回饋。
