# 建構 Oracle 至 PostgreSQL 移轉的整合測試專案框架

為單一目標專案建立具備交易管理和種子資料基礎結構的可編譯空白 xUnit 測試專案。在撰寫測試之前每個專案執行一次。

## 工作流程

```
進度：
- [ ] 步驟 1：檢查目標專案
- [ ] 步驟 2：建立 xUnit 測試專案
- [ ] 步驟 3：實作交易回復基底類別
- [ ] 步驟 4：實作種子資料管理器
- [ ] 步驟 5：驗證專案可編譯
```

**步驟 1：檢查目標專案**

閱讀目標專案的 `.csproj` 以確定 .NET 版本和現有的套件參考。精確符合這些版本 — 不要升級。

**步驟 2：建立 xUnit 測試專案**

- 以受測應用程式相同的 .NET 版本為目標。
- 新增用於 Oracle 資料庫連線的 NuGet 套件 (`Oracle.ManagedDataAccess.Core`) 和 xUnit。
- 僅新增對目標專案的專案參考 — 不新增其他應用程式專案。
- 新增設定為 Oracle 資料庫連線的 `appsettings.json`。

**步驟 3：實作交易回復基底類別**

- 建立一個基底測試類別，在每個測試前開啟交易並在測試後將其回復。
- 攔截並處理所有例外狀況以確保回復。
- 使此模式可供所有下游測試類別繼承。

**步驟 4：實作種子資料管理器**

- 建立一個全域種子資料管理器，用於在交易範圍內載入測試資料。
- 不要認可種子資料 — 交易在每個測試後都會回復。
- 請勿使用 `TRUNCATE TABLE` — 保留現有資料庫資料。
- 建立下游測試建立時將遵循的種子檔案位置命名慣例。

**步驟 5：驗證專案可編譯**

建構測試專案並在完成前確認其編譯零錯誤。

## 主要限制

- **僅限階段 3** — 此 skill 用於建構以 Oracle 為目標的測試專案框架。PostgreSQL 測試專案（階段 6）是透過複製並移轉此專案建立的；在該階段請勿再次執行此 skill。
- Oracle 是黃金行為來源 — 僅為 Oracle 建構框架，而非 PostgreSQL。
- 保持現有的 .NET 和 C# 版本；不要引入較新的語言或執行階段功能。
- 輸出為僅包含基礎結構的空白測試專案 — 不包含測試案例。
