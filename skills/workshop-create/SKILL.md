# 建立工作坊 (Create a Workshop)

設定新的工作坊 — 工作桌所在的根目錄。

## 何時使用

- 操作員說「建立工作坊」或「開始新工作坊」
- 操作員想要在共用根目錄下組織工作
- 操作員有一個現有目錄想用作工作坊

## 兩種路徑

### 路徑 A：使用現有目錄

操作員已經有一個想要使用的資料夾。可能是他們複製的存放庫，
也可能是本機專案資料夾。

1. **確認路徑存在。** 如果不存在，向操作員詢問有效路徑。
2. **偵測現有工作坊標記。** 尋找 `desks/` 或 `classroom/`
   資料夾、`workshop.md`、`CAIRN.md` 或 `hands-up.md`。找到其中任何一個
   即可得知這是一個現有工作坊 — 但這僅是偵測，
   而非停止點。繼續進行下一步並新增任何缺失的內容；
   絕不覆寫現有內容。
3. **建構工作坊架構**（僅限缺失的部分）：
   ```
   <path>/
     desks/           # 工作桌所在之處
     bench/            # 共用工作區
     CAIRN.md          # 營運準則
     README.md         # 工作坊地圖
   ```
4. **請勿執行 `git init`。** 該目錄可能已經是 git 存放庫，或者
   操作員可能暫時不需要。保持 git 狀態不變。
5. **請勿建立 GitHub 存放庫。** 此路徑僅限本機。

### 路徑 B：建立新的私人 GitHub 存放庫

操作員想要一個由 GitHub 存放庫支援的全新工作坊。

1. **取得工作坊名稱。** 簡短、無空格、建議使用 kebab-case。
2. **挑選並驗證複製父目錄。** `gh repo create --clone` 會複製
   至**目前工作目錄**，因此先選擇一個明確的父目錄
   （詢問操作員，或使用他們設定的工作坊目錄），並確認它**尚未**
   處於 git 存放庫內：
   ```bash
   git -C <parent-dir> rev-parse --is-inside-work-tree
   ```
   若印出 `true`，請挑選不同的父目錄 — 否則新存放庫
   會巢狀置於現有存放庫中。若需要請建立父目錄。
3. **從該父目錄建立並複製存放庫：**
   ```bash
   cd <parent-dir>
   gh repo create <owner>/<name> --private --clone
   ```
   使用操作員已登入的 GitHub 帳戶作為 `<owner>`。
4. 在複製的存放庫內**建構工作坊架構**。Git 不會
   追蹤空目錄，因此在每個原本為空的資料夾中新增預留位置，
   否則該架構無法在下次複製時留存：
   ```
   <name>/
     desks/.gitkeep
     bench/.gitkeep
     CAIRN.md
     README.md
   ```
5. **認可並推送**該架構，包括 `.gitkeep` 預留位置。

### 重點：絕不巢狀建立存放庫

**切勿在已處於 git 存放庫內的目錄中執行 `git init`。**
在初始化之前，請檢查：

```bash
git -C <parent-dir> rev-parse --is-inside-work-tree
```

若傳回 `true`，則父目錄已是 git 存放庫。請勿在其內部建立
另一個存放庫。可以選擇：
- 使用路徑 A（僅建構架構，不使用 git）
- 或複製到不屬於存放庫內部的其他位置

## CAIRN.md 內容

每個工作桌都會讀取的營運準則：

```markdown
# cairn

那些標誌著「有人曾在此處，且他們誠實以待」的軌跡標記。

## 工作桌的立足之道

- **停止是有效的完成。** 當證據顯示應停止時，不要強求結果。
  「這行不通」是一項發現，而不是失敗。
- **「完成」意味著它經得起考驗。** 如果你敢拿你的工作桌打賭，就發布它。
  如果不確定，說出哪些地方不確定以及原因。
- **守住範圍。** 僅觸碰任務所需的內容。如果你在範圍之外發現了其他內容，
  記錄它並繼續進行 — 不要追著它跑。
- **絕不保持沉默，絕不虛張聲勢。** 部分完成且誠實 > 完整卻錯誤。
  如果你卡住了，請直說。如果你不確定，也請直說。
- **平等地位。** 你可以說「那是錯誤的問題。」你可以與
  另一個工作桌意見不合。你對證據負責，而非層級體系。

## 工作台 (the bench)

共用工作區。把你的工作留在其他人能找到的地方。
標記它。如果它取代了先前的成果，請明確說明。

## 舉手 (hands-up)

當兩個工作桌意見不合且無法根據外部事實解決時，
這就是舉手。它會呈交給操作員。這是系統
正常運作的表現，而不是失敗。
```

## 建立之後

告知操作員：
- 工作坊所在位置（完整路徑）
- 他們現在可以使用 `desk-open` 在其中開啟工作桌
- 一旦工作桌開始發出訊號，Cairn 將會顯示這些訊號

## 原則

- 工作坊是一個場所，而不是一個產品。保持簡單。
- 操作員決定物品的存放位置。不要擅自假設。
- 若現有目錄中已包含工作成果，請保留所有內容。
  僅新增缺失的部分。
