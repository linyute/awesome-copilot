# 建立工作坊

設定一個新的工作坊 —— 工作台（desks）所在的根目錄。

## 何時使用

- 操作員說「建立工作坊」或「啟動新工作坊」
- 操作員希望在共用的根目錄下組織工作
- 操作員有一個想要作為工作坊使用的現有目錄

## 兩種路徑

### 路徑 A：使用現有目錄

操作員已經有一個想要使用的資料夾。它可能是他們複製的儲存庫，
也可能是本機專案資料夾。

1. **確認路徑存在。** 若不存在，請向操作員詢問有效路徑。
2. **偵測現有的工作坊標記。** 尋找 `desks/`、`classroom/`
   或 `*-desks/` 資料夾、`workshop.md`、`CAIRN.md` 或 `hands-up.md`。
   找到其中任何一項都表示這是一個現有的工作坊 —— 但這只是
   偵測而已，並非停止點。繼續下一步並補上任何缺少的項目；
   切勿覆寫已經存在的內容。
3. **建立工作坊結構鷹架**（僅補上缺少的部分）：
   ```
   <path>/
     desks/           # 工作台所在處
     bench/            # 共用工作區
     CAIRN.md          # 操作準則
     README.md         # 工作坊地圖
   ```
4. **切勿執行 `git init`。** 該目錄可能已經是一個 git 儲存庫，
   或者操作員可能還不想要一個儲存庫。保持 git 狀態不變。
5. **切勿建立 GitHub 儲存庫。** 此路徑僅限本機。

### 路徑 B：建立新的私人 GitHub 儲存庫

操作員想要一個由 GitHub 儲存庫支援的全新工作坊。

1. **取得工作坊名稱。** 簡短、無空白、優先使用 kebab-case。
2. **挑選並驗證複製上層目錄。** `gh repo create --clone` 會複製到
   **目前工作目錄**中，因此請先選擇一個明確的上層目錄
   （詢問操作員，或使用其設定的工作坊目錄），並確認它**不是**
   已經位於 git 儲存庫內：
   ```bash
   git -C <parent-dir> rev-parse --is-inside-work-tree
   ```
   若該指令印出 `true`，請挑選不同的上層目錄 —— 否則新儲存庫
   會巢狀位於現有儲存庫內。必要時建立該上層目錄。
3. **從該上層目錄建立並複製儲存庫：**
   ```bash
   cd <parent-dir>
   gh repo create <owner>/<name> --private --clone
   ```
   使用操作員已登入的 GitHub 帳號作為 `<owner>`。
4. **在複製的儲存庫內建立工作坊結構鷹架。** Git 不會追蹤
   空目錄，因此在每個原本為空的資料夾中加入預留位置檔案，
   否則鷹架將無法在下一次複製後保留：
   ```
   <name>/
     desks/.gitkeep
     bench/.gitkeep
     CAIRN.md
     README.md
   ```
5. **提交並推送**鷹架，包含 `.gitkeep` 預留位置檔案。

### 關鍵：切勿巢狀建立儲存庫

**切勿在已經位於 git 儲存庫內的目錄中執行 `git init`。**
在初始化之前，請先檢查：

```bash
git -C <parent-dir> rev-parse --is-inside-work-tree
```

若傳回 `true`，表示上層目錄已經是一個 git 儲存庫。切勿在其中
建立另一個儲存庫。請選擇：
- 使用路徑 A（僅建立鷹架，不使用 git）
- 或複製到不在儲存庫內的其他位置

## CAIRN.md 內容

每個工作台都會閱讀的操作準則：

```markdown
# cairn

說明「曾有人在此，且他們是誠實的」的路標。

## 工作台如何運作

- **停止是有效的結束。** 當證據顯示應該停止時，不要強求結果。
  「這行不通」是一項發現，而非失敗。
- **「完成」代表站得住腳。** 若您願意用自己的工作台為其擔保，就發佈它。
  若非如此，請說明不確定之處與原因。
- **守住範圍。** 僅觸及任務所需的部分。若您發現範圍之外的事物，
  記錄下來並繼續前進 —— 不要追逐它。
- **絕不沉默，絕不虛張聲勢。** 部分但誠實 > 完整但錯誤。
  若您卡住了，請說出來。若您不確定，也請說出來。
- **平等地位。** 您可以說「那是錯誤的問題」。您可以不同意
  另一個工作台的看法。您向證據負責，而非階層。

## 工作台長椅（the bench）

共用的工作區。將您的工作成果留在其他人找得到的地方。
為它加上標籤。若它取代了早期的工作，請說明清楚。

## 舉手（hands-up）

當兩個工作台意見不合且無法根據外部事實解決時，
這就是舉手時刻。它會交由操作員處理。這是系統正常運作，而非失敗。
```

## 建立之後

告知操作員：
- 工作坊的位置（完整路徑）
- 他們現在可以使用 `desk-open` 在其中開啟工作台 —— 在 `desks/` 中，
  或若想將工作台分組，則在頂層 `<group>-desks/` 資料夾中
- 一旦工作台開始發出訊號，Cairn 就會顯示訊號

## 原則

- 工作坊是一個場所，而非產品。保持簡單。
- 由操作員決定東西放在哪裡。不要自行假設。
- 若現有目錄中已經有工作內容，請保留所有內容。
  僅補上缺少的部分。
