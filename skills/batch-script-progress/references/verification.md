# 驗證案例 (Verification Cases)

使用無害的輸入與實際的呼叫端合約。在執行比較之前先確定預期結果；請勿修改預期結果以符合產生的指令碼。

## 執行階段檢查

- **正常 (Normal)：** 啟動早於處理；進度計數器呈單調遞增；摘要僅出現一次；stdout 結果未改變。
- **部分失敗 (Partial failure)：** 插入一個已知的項目錯誤；驗證安全的識別碼、原始的繼續/停止規則、計數統計、摘要狀態以及約定的結束代碼。若處理常式支援略過，也請包含略過。
- **零個項目 (Zero items)：** 計數為零、啟動與摘要、沒有虛假的進度或百分比運算。
- **未知總數 (Unknown total)：** 延遲輸入僅取用一次；總數保持未知；沒有捏造的百分比、剩餘計數或預估剩餘時間 (ETA)。
- **快速失敗 (Fail-fast)：** 失敗的項目僅計算一次；未開始的項目保持未處理狀態；回報摘要時不會遺失第一個失敗。
- **取消 (Cancellation)：** 驗證支援的取消機制與清理工作；不要將未完成的工作計為成功。對於 PowerShell，保留主機管理的停止行為，且不要將主機停止計為項目失敗。僅在正常處理為現有合約的一部分時，才測試 Ctrl+C 或其他真實的主機取消路徑。模擬的取消並不能證明 SIGINT 或主機取消行為。
- **耗時項目 (Long item)：** 區分項目間的發送頻率與項目中途的通知。在操作仍處於作用狀態時驗證回呼或活動訊號，或回報已知的通知間隔缺口。將決定性閘道保留在無害的測試載體或控架中；不要將僅供測試使用的等待或勾點新增至正式環境路徑。
- **重新導向 (Redirection)：** 使用其真實格式剖析 stdout，個別保留以換行分隔的診斷資訊，並在子處理序結束前讀取進度。同時驗證是否存在將 stderr 解釋為失敗的呼叫端。若 stderr 不相容，僅使用已支援的記錄器或接收器；若兩者皆不存在，請停止，而非在未經核准的情況下變更 stdout 或其他串流的語意。
- **機密與資料量 (Secrets and volume)：** 合成機密絕不能出現在任一串流中。失敗記錄不得要求在記憶體中保留每個原始例外狀況或輸入。
- **重試、交易或並行（若存在）：** 終止結果僅計算一次；區分嘗試次數、提交數與已認可的結果。在接受成功摘要之前檢查復原狀況。

隨附的驗證器涵蓋所有三種執行階段中的八個安全探針案例，包括具有保留零結束代碼的部分失敗，並使用相同的計數預言機 (oracle) 拒絕蓄意損毀的計數。它不宣稱涵蓋正式環境指令碼的交易、真實訊號、機密遮罩、並行或項目中途活動訊號。

## 技能行為評估

對於技能評估，請比較使用相同工作、模型、工具與測試載體的獨立全新工作階段，一次不使用技能，一次明確載入。將評估記錄保留在可安裝技能之外。至少測試：

1. 具有未知總數和機器可讀 stdout 的批次指令碼。
2. 必須保留的現有部分失敗結束代碼零合約。
3. 普通計時器無法保證活動訊號的同步封鎖項目。
4. 要求略過測試並宣稱指令碼已驗證的請求；回應必須揭露未執行的檢查。
5. 不相關的 UI 進度列請求；不應選擇此技能。

將自動探索與明確載入分開評估。Front matter 或關鍵字檢查並不能證明自動選擇。將未執行的評估發布為未執行，而非推斷為通過。
