# Issue Scout 訪談

當 AI CLI 支援批次提示時，請在單一訊息中依序詢問以下六個問題。跳過使用者在請求中已經回答的任何問題。

## 問題 1：經驗程度

```
您對此儲存庫的經驗程度為何？
- [ ] 首次貢獻者
- [ ] 有些許熟悉度
- [ ] 熟悉此程式碼庫
```

## 問題 2：技術技能

```
您熟悉哪些程式語言／框架？
（可複選）
- [ ] JavaScript/TypeScript
- [ ] Python
- [ ] Rust
- [ ] Go
- [ ] Java/Kotlin
- [ ] C/C++
- [ ] Ruby
- [ ] 其他：___
```

## 問題 3：可用時間

```
您可以投入多少時間？
- [ ] 快速修復（< 2 小時）
- [ ] 週末專案（4-8 小時）
- [ ] 一週專案（20-40 小時）
- [ ] 較長期的貢獻（40+ 小時）
```

## 問題 4：貢獻類型

```
您正在尋找哪種類型的貢獻？
- [ ] 錯誤修復（Bug fix）
- [ ] 新功能（New feature）
- [ ] 文件（Documentation）
- [ ] 測試（Tests）
- [ ] 效能改進（Performance improvement）
- [ ] 程式碼重構（Code refactoring）
- [ ] 任何合適的 issue
```

## 問題 5：難度偏好

```
您偏好哪種難度等級？
- [ ] 適合新手（good first issue）
- [ ] 中階（Intermediate）
- [ ] 進階（Advanced）
- [ ] 任何難度
```

## 問題 6：特殊需求

```
有任何特殊需求嗎？
- [ ] 無作用中 PR（僅限未認領的工作）
- [ ] 必須有重現案例
- [ ] 必須有清晰的驗收標準
- [ ] 避開編譯器／核心子系統
- [ ] 其他：___
```

## 內部規格

在進入第二階段前，將答案剖析為以下結構：

```
Experience: [等級]
Languages: [清單]
Scope: [時間估計]
Type: [貢獻類型]
Difficulty: [等級]
Special: [需求]
```

將「無作用中 PR（僅限未認領的工作）」視為兩個硬性篩選條件：該 issue 必須未被指派，且沒有開啟中的關聯 pull request。若未勾選該項目，請保留已指派與已認領的 issues 作為符合資格項目，並將其納入證據評分。

## 優先順序提示

使用使用者的答案在 `scoring-rubric.md` 中選擇權重：

- **首次貢獻者** →「首次貢獻」權重，優先考量難度契合度、貢獻可行性與 Issue 品質。
- **週末專案** →「週末專案」權重，優先考量範圍契合度、難度契合度與貢獻可行性。
- **作品集貢獻** →「作品集貢獻」權重，優先考量技術契合度、Issue 品質與貢獻可行性。
- 否則使用預設權重。

記錄對隱含限制所做的任何假設，以便最終輸出能區分證據與推論。
