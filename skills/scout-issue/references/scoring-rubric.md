# 評分標準

## 維度

### 1. 使用者契合度（User Fit，0-100）
此 issue 與使用者明確與隱含偏好的契合程度如何？

- **高（80-100）**：完全符合所述技能、經驗與偏好
- **中（50-79）**：良好匹配，有輕微差距
- **低（0-49）**：部分匹配或有顯著差距

**考量因素：**
- 技術技能對齊度
- 經驗程度匹配度
- 偏好的 issue 類型
- 是否避開了不希望接觸的領域

### 2. 技術契合度（Technical Fit，0-100）
此 issue 與儲存庫技術堆疊及架構的契合程度如何？

- **高（80-100）**：使用主要技術，程式碼位置清晰
- **中（50-79）**：使用相關技術，需要進行部分程式碼探索
- **低（0-49）**：需要不熟悉的技術或深厚的架構知識

**考量因素：**
- 主要語言／框架匹配度
- 程式碼位置清晰度
- 所需的架構理解程度
- 技術熟悉度

### 3. 範圍契合度（Scope Fit，0-100）
此 issue 與使用者時間及複雜度限制的契合程度如何？

- **高（80-100）**：明確位於所述範圍內
- **中（50-79）**：略超出範圍但仍可達成
- **低（0-49）**：顯著超出範圍

**考量因素：**
- 估計時間對比請求時間
- 複雜度對比請求複雜度
- 受影響的檔案／元件數量
- 外部相依性

### 4. 難度契合度（Difficulty Fit，0-100）
此 issue 與使用者技能水準的契合程度如何？

- **高（80-100）**：適當的挑戰等級
- **中（50-79）**：略高／略低但可應付
- **低（0-49）**：過於簡單或過於困難

**考量因素：**
- 所需的專業知識水準
- 涉及的學習曲線
- 先前的類似工作
- 可用的文件／協助

### 5. Issue 品質（Issue Quality，0-100）
此 issue 的定義明確程度與可執行性如何？

- **高（80-100）**：清晰的問題、重現步驟與驗收標準
- **中（50-79）**：良好的描述，有部分缺口
- **低（0-49）**：模糊、需求不明確

**考量因素：**
- 問題描述清晰度
- 是否提供重現步驟
- 是否定義驗收標準
- 範例／預期行為

### 6. 活躍度（Activity，0-100）
此 issue 及其相關討論的活躍程度如何？

- **高（80-100）**：維護者近期有活動，興趣明確
- **中（50-79）**：有些許活動，合理的回應時間
- **低（0-49）**：過時，近期無活動

**考量因素：**
- 維護者最後一次留言
- 整體 issue 活動
- 相關 PR 活動
- 社群關注度

### 7. 貢獻可行性（Contribution Feasibility，0-100）
使用者實際完成此貢獻的可行性有多高？

- **高（80-100）**：清晰的完成路徑，低風險
- **中（50-79）**：透過部分研究／學習即可達成
- **低（0-49）**：重大的未知因素或阻礙項目

**考量因素：**
- 用於驗證變更的現有測試
- 清晰的實作路徑
- 被拒絕的風險較低
- 可用的指引

### 8. 證據品質（Evidence Quality，0-100）
支持此建議的證據有多強有力？

- **高（80-100）**：多個強有力的證據點
- **中（50-79）**：良好的證據，有部分缺口
- **低（0-49）**：薄弱或不足的證據

**考量因素：**
- 清晰的重現案例
- 維護者確認
- 無阻礙的 PR
- 近期活動

## 權重設定

### 預設權重
- 使用者契合度：20%
- 技術契合度：15%
- 範圍契合度：20%
- 難度契合度：15%
- Issue 品質：10%
- 活躍度：5%
- 貢獻可行性：10%
- 證據品質：5%

### 權重調整

這三個具名情境會重新調整部分維度的權重，並**按比例**縮減其餘維度，使權重總和仍為 100%。

「按比例」的計算方式：令 S 為指派給提升維度的權重總和。剩餘權重為 `100 - S`，由未提升的維度依其預設權重比例分攤：

```
reduced_weight(d) = default_weight(d) × (100 - S) / sum_of_defaults_of_unpromoted
```

## 計算方式

最終分數 = Σ (維度分數 × 權重)

其中每個維度分數為 0-100，權重總和為 1.0。

### 完整範例（「週末專案」）

分數：使用者契合度 60、技術契合度 80、範圍契合度 90、難度契合度 70、
Issue 品質 85、活躍度 40、貢獻可行性 75、證據品質 50。

| 維度 | 分數 | 權重（週末） | 貢獻分數 |
|---|---|---|---|
| 使用者契合度 | 60 | 9% | 5.40 |
| 技術契合度 | 80 | 7% | 5.60 |
| 範圍契合度 | 90 | 30% | 27.00 |
| 難度契合度 | 70 | 25% | 17.50 |
| Issue 品質 | 85 | 5% | 4.25 |
| 活躍度 | 40 | 2% | 0.80 |
| 貢獻可行性 | 75 | 20% | 15.00 |
| 證據品質 | 50 | 2% | 1.00 |

最終分數 = 5.40 + 5.60 + 27.00 + 17.50 + 4.25 + 0.80 + 15.00 + 1.00 = **76.55**

## 信心水準

**高信心水準：**
- 分數 ≥ 80
- 跨多個維度的強有力證據
- 清晰的實作路徑
- 活躍的維護者支援

**中信心水準：**
- 分數 60-79
- 良好的證據，有部分缺口
- 可達成但可能需要研究
- 合理的維護者興趣

**低信心水準：**
- 分數 < 60
- 薄弱或不足的證據
- 重大的未知因素
- 維護者意圖不明確
