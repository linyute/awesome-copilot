# UI/UX 設計指引

## 工作流程

1. 識別目的、使用者問題、受眾/裝置、平台、架構、元件函式庫、現有設計系統/權杖、斷點、暗色模式需求與無障礙功能限制。
2. 選擇下方的平台分支。套用共用規則及其專屬需求。
3. 保留既有模式，除非任務概要要求變更。實作最小符合標準的解決方案。
4. 驗證權杖、響應式行為、語意、鍵盤/螢幕報讀器使用、對比度、焦點、觸控目標、狀態與減少動態效果。

## 平台分支

### Web 與桌面

- 在使用 ARIA 之前先使用語意 HTML；維持邏輯焦點順序、可見焦點，以及指標/鍵盤對等性。
- 驗證斷點、易讀的行長、無水平溢出，以及最小 44×44px 目標。
- 保留元件函式庫/版面配置系統；偏好僅使用 CSS 的動態效果。

### iOS

- 遵循 Apple HIG 的導覽、系統圖示、動作表/強制回應視窗 (sheets/modals)、回饋與手勢規範。
- 處理安全區域、瀏海/動態島、狀態/主畫面指示條、鍵盤與橫向模式。
- 支援 VoiceOver、動態字級 (Dynamic Type) 與減少動態效果。目標：≥44pt 且間距 ≥8pt。
- 偏好 SF Pro/目前系統字型與系統回饋色彩；將共用語意角色對應至 iOS 權杖。
- 使用適當的彈簧動畫時序；將觸覺回饋與視覺或文字回饋配對。

### Android

- 遵循 Material 3 的應用程式/導覽列或導覽軌、FAB、卡片、對話方塊、導覽與按下狀態規範。
- 處理狀態列、手勢導覽、鍵盤、挖孔螢幕、直向與橫向模式。
- 支援 TalkBack、字型縮放與減少動態效果。目標：≥48dp 且間距 ≥8dp。
- 偏好 Roboto/目前系統字型與 Material 3/權杖化色彩；僅在適當時使用動態色彩。
- 使用海拔高度 (elevation)/動態權杖與具無障礙特性的按下/狀態回饋。

### 跨平台行動端

- 共用語意權杖與內容/互動階層。僅透過 `Platform.select` 或架構介接器對應真實的平台差異（導覽、字體排印、海拔高度/陰影、安全區域、手勢、系統回饋、觸覺回饋）；切勿為了表面差異而複製整個設計。
- 在 React Native、Expo 或 Flutter 中，偏好目前的元件函式庫/主題，接著是 `StyleSheet.create` 或架構主題。絕不針對靜態值使用行內樣式。
- 支援 iOS/Android 文字縮放，且不裁切或隱藏必要操作。

### 共用行動端檢查

- 使用 8pt 網格，除非設計系統定義了相容的比例尺度。
- 測試挖孔螢幕/系統列/主畫面指示條、鍵盤重疊、手勢衝突、可及性、旋轉、捲動、效能、螢幕報讀器順序與大型文字。
- 定義載入中、空白、錯誤、重新整理、內容、已選取、已停用與現用狀態。
- 提供架構所需的無障礙標籤、角色、提示與狀態值。

## `DESIGN.md` 合規性

使用 Google DESIGN.md alpha 格式：

1. YAML frontmatter：`version`、`name`、`description`、`colors`、`typography`、`rounded`、`spacing`、`components`。
2. 標準內文順序：`## Overview`、`## Colors`、`## Typography`、`## Layout`、`## Elevation & Depth`、`## Shapes`、`## Components`、`## Do's and Don'ts`。
3. 涵蓋品牌基本原理；語意調色盤；字型階層；間距/網格/容器寬度；表面層級或扁平替代方案；圓角半徑/邊框；元件定義；實務防護措施。

每個 YAML `components:` 值必須是 `{token.ref}`——絕不可為行內色彩、間距、尺寸或其他原始值。可用時執行 `npx @google/design.md lint DESIGN.md`。

## 前端美學

- 將規格不足的概要立足於具體的主題、受眾與主要任務上。從其素材、工具與詞彙中衍生真實文案與視覺線索——而非可重複使用的主題。
- 選擇一個連貫的方向與一個有理有據的標誌性元素。將大膽設計集中於該處；保持支援性元素克制並移除無目的的裝飾。
- 讓 Web 首頁橫幅 (hero) 透過特色內容或互動展示產品的核心構想；除非合理，否則避免公式化的指標/漸層構圖。
- 僅使用編號、分隔線、標籤與上眉標 (eyebrows) 來傳達階層、順序或類別。
- 使執行與方向相符：極繁主義 (maximalism) 需要景深/細節；極簡主義 (minimalism) 需要精確的字型、間距與對齊。修改任何可能屬於任何產品的平庸設計。
- 預設保留既有的字體排印、版面配置、表面、效果、元件、清單、圖示與導覽。沒有針對任務的特定理由，不要拒絕標準字型、純色表面或可預測的網格。
- 僅在需要時選擇獨特的展示/內文字型配對；透過專案方法載入字型。行動端預設：iOS 為 SF Pro，Android 為 Roboto。僅在跨平台品牌推廣中使用對應的共用字型（例如 `expo-font`、`react-native-google-fonts` 或內嵌資產）。
- 使用現有權杖/CSS 變數。僅在符合設計系統時套用 60-30-10 法則。

## 色彩策略（暗色模式）

- 反轉表面，同時保留文字對比度；保持強調色可識別，並在適當時以克制的微光/表面對比取代厚重的陰影。
- 在兩種主題中驗證每個語意角色。跨平台共用角色並將其對應至平台權杖；絕不硬編碼分開的調色盤。
- 僅在適合產品且與權杖相容時使用 OLED 純黑。在 Android 上，使用 Material 3 暗色主題或同等權杖。

## 動態效果與動畫

- 精心編排頁面載入動態；不要為所有元素都加上動畫。定義一致的持續時間/緩動效果 (easing)。
- 在 Web/桌面上偏好 CSS。在行動端上，使用平台彈簧動畫或 Material 權杖，並將手勢進度對應至狀態。
- 每個非必要動畫必須支援減少動態效果，透過移除、縮短或替換動作而不遺失資訊或影響任務完成。觸覺回饋絕不可為唯一的回饋形式。

## 版面配置創新

合理時允許：非對稱網格、受控的重疊/負外距/z-index、便當盒 (bento) 或對角流動、包含受限內容的滿版媒體、不同高度的行動端清單、貼齊捲動 (snap scrolling)、易觸及的浮動控制項，以及感知安全區域的底層動作表 (bottom sheets)。保持其具響應性、易讀性、可透過鍵盤存取，且無非預期的水平溢出。

## 無障礙功能與狀態

- 對比度：一般文字 ≥4.5:1；大型文字與合格 UI 元件 ≥3:1。焦點指示器需要足夠的對比度。
- 在準確且必要的 ARIA 之前先使用語意 HTML。確保鍵盤存取與邏輯焦點順序。
- 目標：Web/桌面 ≥44×44px，iOS ≥44pt，Android ≥48dp。
- 測試 VoiceOver/TalkBack 與文字縮放，且不裁切或隱藏基本內容。
- 絕不單靠動態效果傳達訊息。驗證空白、載入中、錯誤、滑鼠懸停、焦點、現用、停用與選取狀態。

## 樣式套用優先順序

依序套用：

1. 元件函式庫/全域主題設定。
2. 函式庫屬性/主題屬性（例如 NativeBase、React Native Paper、Tamagui）。
3. 使用權杖的 `StyleSheet.create` (React Native) 或架構主題 (Flutter)。
4. `Platform.select` 僅用於陰影、字型或間距等真正的差異。
5. 行內樣式僅用於執行時期動態值——絕不用於靜態值。

## 規則

- 全新 UI 預設為現代、專業、具凝聚力、響應式、具無障礙功能且獨特。保留既有的視覺語言與已核准的交接產物，除非明確進行重新設計。
- 避免千篇一律的卡片網格、非必要的容器/藥丸標籤、無意義的漸層/毛玻璃效果、過度的圓角、裝飾性圖示、填塞文案與裝飾性動態效果。每種處理方式必須支援階層、品牌、預設用途 (affordance) 或回饋。
- 使用 `DESIGN.md` 權杖與 `StyleSheet.create`；無硬編碼或靜態行內樣式。
