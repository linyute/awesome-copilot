# 錯誤重現簡報 (Bug Reproduction Brief)

當錯誤報告不完整、間歇性、特定於環境或混雜了假設的原因時，使用此技能。目標是在診斷或修復開始之前，證明最小的可觀察故障。

## 1. 記錄觀察到的故障

擷取確切的錯誤、不正確的輸出、時間戳記、受影響的路由或指令，以及已知最小的輸入。在不含機密或個人資料的情況下保留相關記錄。將二手描述標記為未驗證。

## 2. 識別環境

僅記錄您可以檢查的事實：

- 存放庫與提交 (commit)；
- 執行階段與套件管理工具版本；
- 作業系統或容器；
- 相依性鎖定檔案；
- 相關的功能旗標；
- 目標是本機、測試、預行 (staging) 還是生產環境。

切勿猜測認證或生產設定。

## 3. 分離預期與實際行為

撰寫兩個明確的可觀察陳述：

```text
Expected: [可觀察的結果]
Actual:   [可觀察的結果，包含狀態或錯誤]
```

請勿在任一陳述中放入懷疑的原因。

## 4. 縮減重現步驟與資料

從報告的路徑開始，然後一次移除一個不相關的資料、服務和步驟。保留仍會失敗的最小測試裝置 (fixture)。若故障停止發生，請還原最後移除的條件並予以記錄。

優先選擇隔離的測試、最小指令碼或最小安全請求，而非針對生產環境進行重現。

## 5. 證明可重複性

在安全的情況下至少執行兩次最小重現。記錄指令與輸出。若故障為間歇性，回報觀察到的頻率與持續時間，而不是稱其為確定性的。

## 6. 在修復前停止

經過驗證的重現就是交付成果。在建立簡報時不要編輯實作程式碼，因為那可能會破壞證據或將診斷與補救措施混淆。

## 輸出

```markdown
# Bug Reproduction Brief

- 目標與提交：
- 環境：
- 預期：
- 實際：
- 最小步驟：
- 最小測試裝置：
- 重現結果：是 / 否 / 間歇性
- 證據：
- 未知事項：
- 待測試的安全下一步假設：
```

## 安全邊界

- 不要僅為了重現錯誤而變更生產資料。
- 不要發佈機密、客戶記錄或私人原始碼。
- 不要僅憑相關性就聲稱根本原因。
- 優先使用唯讀或可逆的探索。
- 在經過驗證的重現後停止；診斷與修復是獨立的工作流程。

## 範例提示詞

```text
對失敗的結帳測試使用 Bug Reproduction Brief 技能。先不要修復它。將其縮減為最小的安全失敗測試裝置，並回報確切的指令證據、預期結果、實際結果以及剩餘的未知事項。
```
