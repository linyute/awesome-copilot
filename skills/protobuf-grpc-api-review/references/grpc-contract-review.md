# gRPC 協定審查

當變更影響服務、方法、請求/回應行為或用戶端/伺服器端政策時，使用此參考資料。僅套用與變更相關的檢查。

## 方法識別與形狀

完整套件名稱、服務名稱與方法名稱構成 RPC 識別身分。重新命名或移動其中任何一項都會變更方法路徑，並破壞現有用戶端、路由、授權政策、可檢測性（observability）與服務設定。

將下列情況視為破壞性協定變更：

- 移除或重新命名服務或方法
- 變更請求或回應訊息類型
- 變更單一（unary）、用戶端串流、伺服器端串流或雙向串流模式
- 將服務移至另一個 protobuf 套件

優先採用新增方法、移轉呼叫者、淘汰舊方法，並在相容性期間結束後才將其移除。使用 protobuf 相容性規則審查請求與回應訊息的變更。

## 期限與取消

- 用戶端應設定切合實際的期限（deadline）；gRPC 預設不設定期限。
- 期限必須涵蓋預期的網路與處理延遲，並對照實際上線或負載測試依據進行驗證。
- 當呼叫被取消或其期限到期時，伺服器必須停止衍生的工作。
- 下游呼叫應接收剩餘的期限，而非重新啟動全新完整的逾時。請確認傳遞是自動進行還是必須在實作語言中明確啟用。
- 不要將期限或取消轉換為容易誤導的應用程式狀態。

當新的未受限呼叫、被吞掉的取消或可能比原始請求存活更久的下游工作會產生資源或正確性風險時，請予以標註。

## 重試與等冪性

在建議或核准重試政策之前，請先回答：

1. 此操作是否可以在不重複變更狀態的情況下重複執行？
2. 若結果不明確，是否存在等冪性索引鍵或伺服器端重複資料刪除期間？
3. 此方法可重試哪些狀態碼？
4. 嘗試次數是否受到最大嘗試次數、指數輪詢退避、隨機抖動（jitter）、節流與總體期限的限制？
5. 重試嘗試次數與最終呼叫結果是否可被觀察？

gRPC 實作中啟用了重試，但沒有預設的通用重試政策；透明重試在有限情況下仍可能發生。回應標頭會確認（commit）RPC 並結束 gRPC 重試嘗試。絕不能僅因變更性 RPC 回傳 `UNAVAILABLE` 或 `DEADLINE_EXCEEDED` 就將其視為可安全重試：伺服器可能已經套用了變更。

## 狀態碼是 API 的一部分

將狀態變更視為可觀察的行為進行審查。優先使用最具體穩定的代碼，並確保錯誤詳細資訊不含機密。

- `INVALID_ARGUMENT`：無論系統狀態為何皆無效
- `FAILED_PRECONDITION`：僅在狀態明確修復後才重試
- `ABORTED`：重試較大的交易或「讀取-修改-寫入」序列
- `UNAVAILABLE`：暫時性失敗，重試此呼叫可能是適當的
- `RESOURCE_EXHAUSTED`：配額或容量已耗盡
- `UNAUTHENTICATED`：認證遺失或無效
- `PERMISSION_DENIED`：已通過驗證的呼叫端缺乏權限
- `NOT_FOUND`：資源不存在，或刻意隱藏存在性是授權協定的一部分

避免將領域失敗替換為 `UNKNOWN` 或 `INTERNAL`。在變更既有代碼之前，請檢查用戶端邏輯、重試政策、計量指標與警示。

## 串流協定

對於串流方法，建立並測試：

- 訊息順序以及是否可能重複
- 半關閉（half-close）與完成語意
- 反壓（backpressure）與受限緩衝
- 單一訊息與總串流大小限制
- 雙方的取消與清理
- 長期連線串流的驗證有效期限
- 中斷後的繼續、重播或檢查點行為

不要將串流作為預設改進項目；需要具體需求與明確的生命週期協定。

## 安全性與資源邊界

- 針對每個方法強制執行驗證與授權；每當新增方法時，更新列舉路徑的政策對應表。
- 使用適合部署環境的傳輸安全性，避免記錄憑證或敏感 metadata。
- 在輸入不受信任的情況下，限制請求大小、回應大小、並行性、展開度（fan-out）與昂貴的重複欄位。
- 在開始不可逆或昂貴的工作之前進行驗證。
- 檢查反映（reflection）、健康服務與偵錯端點是否僅依預期公開。

## 行為演進

結構描述相容性並不能保護語意協定。審查以下變更：

- 表示為選用 protobuf 欄位的必填業務欄位
- 分頁權杖、排序、篩選條件與一致性保證
- 等冪性與重複資料刪除鍵
- 部分成功與批次錯誤語意
- 預設限制、配額與伺服器端逾時
- 錯誤詳細資訊與修飾遮蔽

對於行為變更，需要有文件與測試來涵蓋推出與復原期間的舊用戶端。

## 針對性驗證

- 在支援混合版本時，針對新伺服器呼叫舊的產製用戶端，並針對舊伺服器呼叫新用戶端
- 透過 Proxy、閘道與授權中介軟體測試確切的方法路徑
- 執行期限、取消與下游傳播測試
- 注入可重試與不可重試的失敗，包括狀態變更後的不明確失敗
- 適用時測試串流取消、慢速取用端、大型訊息與中斷的串流
- 驗證計量指標能否區分嘗試次數與邏輯呼叫
