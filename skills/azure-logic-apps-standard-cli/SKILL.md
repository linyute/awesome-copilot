# Logic Apps Standard CLI

使用 `az logicapp` 作為支援的 Standard 專案、工作流程、
連線、驗證、執行階段、診斷、測試與打包作業的主要介面。
請勿手動重新建立由受支援命令所擁有的檔案或 Azure 連接配置。
在 CLI 未接管該作業之處，手動工作流程編寫、工作區檔案、忽略檔案
以及基礎結構即程式碼 (IaC) 仍屬合適做法。

檢視基準：擴充功能 **1.0.0b1**。此為供評估與
開發使用的公開**預覽版** (preview)，並非已具備生產環境就緒狀態的保證。請使用非生產
環境資源進行評估。現有的核心應用程式管理、應用程式設定以及 ZIP 部署命令
與此擴充功能的預覽命令有所區別，即使參考頁面將擴充功能命令
標示為正式推出 (GA) 亦然。宣告的平台支援並不等於線上執行階段的資格審查。

## 強制性程序路由

此資料夾為單一可安裝的 Skill 套件。隨附檔案的解析是相對於此
`SKILL.md`，而非客戶的工作目錄。請安裝／複製整個資料夾。
這些參考資料為必要程序，而非可有可無的背景閱讀。
安裝、來源與維護注意事項請參閱 [套件 README](README.md)。

**在進行對應的作業之前，請先閱讀下列所有適用的參考資料。**
對於複合型工作，請在各階段開始前閱讀所需的程序。若必要
檔案遺失或無法讀取，請將該作業回報為受阻。請勿憑空捏造
語法、繞過其必要條件，或抓取未經審查的替代方案。

| 要求的作業 | 必要的隨附程序 |
|---|---|
| 安裝／檢查相依性；診斷、啟動或停止主機 | [本機執行階段](references/local-runtime.md) |
| 探索連接器；建立／變更／測試／刪除連線；設定身分識別或 ACL | [連線與身分識別](references/connections.md) |
| 檢查／匯出／變更線上工作流程；叫用／診斷／取消／重放執行 | [線上工作流程與執行](references/live-operations.md) |
| 產生基本架構、規劃、執行或檢查原生工作流程測試 | [工作流程測試](references/testing.md) |
| 打包、部署或變更部署排除項目 | [打包與部署](references/packaging-deployment.md) |

基本的本機基本架構產生、工作區建立與離線驗證均在此處詳細說明。
請勿僅僅因為啟動了此 Skill 就啟動主機、還原套件、叫用工作流程或變更 Azure。
僅選取所要求工作所需的程序。

## 不容妥協的規則

1. **變更前先檢查。** 確認實際的專案根目錄與要求的範圍。
   檢查受影響的工作流程、組態結構／參考、忽略檔案、
   工作區以及未認可的變更。請勿傾印機密設定值。
2. **保留既有慣例。** 請勿在未經要求的情況下重構存放庫、轉換工作流程
   種類、遷移驗證機制、正規化別名或替換使用者檔案。
3. **預設使用受控識別。** 針對新連線與已部署的應用程式組態，
   僅在客戶明確要求或選取的連接器／作業不支援時，才使用
   其他驗證方法。驗證失敗並不代表缺乏支援。絕對不可無提示地退回至秘密。
4. **將啟用身分識別作為新專案交付的一部分。** 設定受支援的本機
   以身分識別為基礎的連線機制。針對面向部署的工作，請透過
   經授權的佈建／部署流程啟用應用程式身分識別。保留既有的身分識別
   慣例；否則預設為系統指派的受控識別。本機基本架構產生並未
   授權進行 Azure 變更；請明確回報未經核准的雲端必要條件。
5. **確認不同的主體與權限。** 本機處理程序不會取得
   已部署應用程式的受控識別。請遵循連接器所記錄的本機機制；
   請勿假設每個連接器都使用 `DefaultAzureCredential`。請分開確認
   本機與雲端主體、連線存取權限以及最低權限的資料平面角色。
6. **透過探索而非猜測。** 從實際的執行階段或區域受控目錄中取得
   連接器識別碼、作業識別碼、參數集以及必要的輸入結構。使用
   Metadata 與權威連接器文件驗證驗證機制支援。
7. **保護秘密與機密輸出。** 絕對不要在命令引數、原始碼控制、範例或共用
   記錄中放入秘密值。將現有定義、匯出項目與提供者輸出視為具有潛在機密性；
   在共用前進行保護與審查。使用受支援的 stdin 秘密輸入與設定參考。允許
   必要的受保護本機／執行階段儲存體；本機設定與測試產物必須被忽略並排除於部署之外。
8. **保持環境可設定性。** 將部署專屬的端點、資源識別碼以及
   環境數值放在設定或參數中，而非硬式編碼於工作流程常值內。
9. **防範替換與並行存取風險。** 在每次建立前進行檢查；將建立作業
   視為非等冪 (non-idempotent)。僅針對經審查的替換使用 `--force`。在替換／刪除
   之前先匯出線上工作流程、保留修訂版本，並在進行非不可分割 (non-atomic)
   寫入前取得核准。請勿繞過衝突或盲目重試結果未明的變更作業。
10. **授權實際影響，而非僅授權目標。** 啟動本機觸發程序與執行測試／建構
    程式碼可能會與真實系統通訊。首先確定允許的影響範圍。針對 Azure 變更、
    取消與重放取得明確授權；預覽版並非沙盒。
11. **保持佐證誠實。** 即使結束代碼非零，也要讀取結構化結果。請清楚區分
    已設定、已授權、已接受、已觀察以及已驗證的狀態。開啟的連接埠、已接受的
    叫用、產生的規劃或已檢查的報告並不代表工作流程執行成功。
12. **驗證而不偽造成功結果。** 進行漸進式驗證；在發佈打包／部署之前
    要求嚴格的完整專案驗證。保留更嚴格的存放庫政策。請勿僅為了
    取得通過結果而移除警告、判斷提示、輸出或防護機制。
13. **精確負責清理工作。** 除非被要求保持執行，否則僅停止由該工作所屬的
    執行階段；驗證關閉狀態與共用相依性的所有權。絕不可依名稱終止處理程序
    或停止其他使用者的主機／模擬器。
14. **嚴守部署邊界。** 合併忽略規則而不替換無關的項目；檢查實際的
    套件內容。請勿將本機設定、測試、狀態、編輯器檔案、記錄、設定範本
    或產生的套件部署出去。
15. **保留連接器的專門語法語意。** 針對傳遞保證、有害訊息處理 (poison handling)
    以及特定作業的測試，使用適用的連接器專屬指引。若無可用指引，請使用權威
    連接器文件；請勿捏造專門行為。

## 預設值與重要抉擇

| 決策項目 | 規則 |
|---|---|
| 工作流程種類 | 保留既有種類；新工作流程預設為 Stateful |
| Stateful 與 Stateless 之抉擇 | 需具備持久歷史記錄／長時間執行的工作採用 Stateful；適合短期、低延遲的工作則審慎選擇 Stateless |
| 初始範圍 | 本機編寫，除非要求中包含進一步的作業 |
| 驗證機制 | 受控識別，僅受限於上述例外狀況 |
| 身分識別類型 | 沿用既有慣例，否則為系統指派；若有明確的穩定／共用／預先佈建身分識別需求則為使用者指派 |
| 專案根目錄／配置 | 沿用既有存放庫慣例；否則採用最小合適配置 |
| 工作區 | 選用；重複使用既有工作區，僅在意圖不明時詢問 |
| 內容環境 (Context) | 選用的儲存捷徑；未經授權絕對不變更目前使用中的選取項目 |
| 自動化作業 | 明確的專案路徑與執行階段／雲端目標座標 |
| 執行階段生命週期 | 檢查完畢後停止工作專屬的主機，除非被明確要求保留它們 |

從要求／存放庫推斷路徑與已確立的選擇。僅就遺漏的重要決策
進行詢問。已知答案時請勿堅持詢問三個基本架構問題。

## 1. 驗證工具並選取目標

首先進行檢查；這些命令不會安裝擴充功能：

```azurecli
az version
az extension list --query "[?name=='logicapp'].{name:name,version:version}" --output table
```

檢視版本之最低要求：Azure CLI 2.67.0 及其 Python 執行階段 3.10。
若擴充功能不存在且已獲授權安裝，請使用公用擴充功能索引：

```azurecli
az extension add --name logicapp --version 1.0.0b1 --allow-preview true
az extension show --name logicapp --output json
az logicapp --help
```

在每個命令執行後檢查結束狀態；安裝失敗後請勿繼續執行。
若要求的版本無法使用，請回報索引／網路／版本錯誤。
請勿使用私有 wheel 替代、停用 TLS 或繞過組織的套件政策。
請勿自動升級已安裝的擴充功能。若安裝的是不同版本，
在執行前請檢查每個受影響命令的 `--help` 與目前的官方合約；
若有實質差異應予以回報，而非假設此基準依然適用。

在使用範例之前先偵測作業系統與 Shell。單行 `azurecli` 區塊可避免各 Shell 專屬的
行接續符號。`App`、`Orders` 與大寫識別碼皆為示範性名稱：請替換為
實際檢查出的目標、為含有空格的路徑加上引號，並使用主機作業系統的路徑分隔符號。
運算式的 PowerShell／原生包裝函式引號規則在連線程序中有詳細規定。

| 作業 | 目標合約 |
|---|---|
| 本機檔案編寫／驗證 | 明確的 `--path`；部分命令亦接受本機內容環境 (context) |
| 執行階段 API 檢查／執行 | `--local --port PORT`，或雲端 `--resource-group GROUP --name APP` |
| 執行階段生命週期 | 本機 `runtime start/show/stop` 旗標；非雲端主機管理 |
| 執行階段健康檢查 (doctor) | 本機 `--path` 與選用的 `--port`，或本機 `--context`；無 `--local` |
| 受控連線建立 | `--name CONNECTION` 與 `--logic-app-name APP`，兩者不可混用 |
| 線上工作流程啟用／停用 | 僅限已部署的應用程式 |

針對以 API 為目標的命令，明確指定 `--port` 時必須加上 `--local`。具名內容環境擁有自己的
座標：請勿將其與明確的 API 目標旗標混用。請檢查特定命令的說明以了解
檔案命令與內容環境的組合規則；請勿假設存在通用的優先順序規則。
雲端工作需要預期的 Azure 登入、租用戶、訂用帳戶與權限。
請獨立驗證帳戶選取狀況：已儲存的內容環境不會綁定訂用帳戶／租用戶。
避免變更全域帳戶選取項目；在自動化作業中建議使用明確的 `--subscription`。

## 2. 於本機檢查並產生基本架構

將目的地歸類為全新、既有的 Standard 專案，或是非空的不明
目錄。**專案／主機根目錄包含 `host.json`**；工作流程目錄為其直接
子目錄。存放庫根目錄本身亦可能就是該專案根目錄。

針對既有專案，檢查 `host.json`、工作流程檔案、`connections.json`、
存在時的 `parameters.json`、設定名稱／參考、忽略檔案、工作區以及
受影響的未認可變更。保留無關內容並避免公開本機數值。

針對新專案，根據需求選擇位於根目錄的極簡專案配置，或是方案／monorepo 子
專案。諸如 docs、requests、fixtures、tests、logs 與 artifacts 等支援目錄
均為選用，僅在實際需要時建立。建議將套件輸出置於主機根目錄之外。
請勿手動編寫 `.azurelogicapps` 執行階段狀態。

檢查目的地後，使用明確路徑產生基本架構：

```azurecli
az logicapp project create --path App --workflow Orders
```

僅在刻意選擇 Stateless 時才加上 `--workflow-kind Stateless`。
僅在經過審查的非空不明目錄中使用 `--adopt`，不可將其作為常規設定步驟。
在擴充產生的 host／settings／connection／workflow 檔案之前先進行檢查。
建立額外的工作流程而不替換既有工作流程：

```azurecli
az logicapp workflow create --path App --workflow Notify --kind Stateful
```

`--file FILE` 接受經審查的完整工作流程檔案或純定義以進行本機匯入。
建立作業僅限本機執行且非等冪。請勿用它來新增雲端工作流程。

在寫入機密的本機設定之前，請確認有效的 Git 排除規則。請相對於
實際存放庫與主機根目錄合併規則；絕不可將 `.gitignore` 覆蓋至 `.funcignore`。
一律將本機設定／狀態排除在原始碼控制與部署之外。若要變更
部署排除項目，請先閱讀打包程序並遵循其具體規則。

**檢查關卡：** 正確的專案根目錄、要求的工作流程種類、保留的使用者檔案、有效
的秘密排除項目，以及以身分識別為基礎的組態或明確回報的先決條件。

## 3. 選用的工作區與內容環境 (Context)

`.code-workspace` 檔案為選用；直接開啟主機目錄亦為有效做法。重複使用既有
工作區。當要求建立新的多根工作區時，請使用指向真實資料夾的相對路徑，
並將 Logic Apps 主機專案置於首位。請勿僅為了填入內容而建立空資料夾。
請依選取的配置調整此 JSON；這並非強制的檔案名稱或資料夾架構：

```json
{
  "folders": [
    { "name": "Logic App", "path": "App" }
  ]
}
```

保留既有的工作區設定與名稱。僅在實用且存在時新增 docs/test 根目錄。
對於專案位於根目錄的工作區，專案路徑為 `"."`。

已儲存的內容環境為選用項目。在選擇專屬的專案專用名稱之前，
先檢查 `context list`。若有要求，建立捷徑但不隱含選取它：

```azurecli
az logicapp context list --output table
az logicapp context create --name orders-local --path App --port 7071
az logicapp context show --name orders-local
```

僅在切換使用中選取項目獲授權時，才使用 `context use --name NAME` 或建立時的 `--use`。
`context update` 會保留省略的欄位且不會選取目標；編輯使用中的
目標會跳出提示，除非 `--yes` 已獲授權。種類變更需要明確的本機路徑／連接埠
或雲端資源群組／應用程式座標。變更種類前請先檢查其說明。
`context delete` 僅刪除捷徑；刪除使用中的捷徑會清除選取狀態而不會
自動選擇替代項目。儲存位置依循 `AZURE_CONFIG_DIR`；其中不可包含認證。

## 4. 編寫與驗證

保留工作流程結構／種類。使用穩定不變的動作／觸發程序名稱。實作必要的
順序、分支、重試、逾時與失敗路徑；終端成功與失敗路徑
不可同時執行。使用探索出的作業結構與可設定的環境數值。
僅在需要時建立具代表性的非機密測試受測物 (fixtures)。

針對內建連接器探索，在建立安全的主機啟動並查詢目錄之前，
請先閱讀本機執行階段與連線這兩份程序文件。對於需要執行階段支援的
驗證，請先閱讀本機執行階段程序並確立就緒狀態。
原生測試則可改用自行編寫的模擬 (mocks)，而無需啟動主機。

驗證正在作用中開發的工作流程：

```azurecli
az logicapp workflow validate --path App --workflow Orders
```

針對已完成的專案編寫以及在發佈打包／部署之前：

```azurecli
az logicapp workflow validate --path App --all --fail-on-warning
```

當需要執行階段支援的驗證時，請先確立主機就緒狀態：

```azurecli
az logicapp workflow validate --path App --all --fail-on-warning --with-runtime --local --port 7071
```

請勿僅為了離線編輯／檢視而啟動主機。評估各項發現並保留存放庫
政策；分開回報無關的既有失敗，而不削弱發佈關卡要求。
靜態驗證、執行階段範本驗證、原生判斷提示以及線上整合

## 完成佐證

僅套用與所要求工作相關的關卡；請勿將檢查工作演變成部署工作。

| 工作 | 必要佐證 |
|---|---|
| 基本架構產生／編寫 | 要求的文件／種類與行為；受影響部分的驗證；無未經要求的架構重組 |
| 連線／身分識別 | 探索到的結構、設定參考、選取的主體、經確認的授權或明確的受阻狀況；未洩漏秘密 |
| 完整專案發佈 | 嚴格的完整專案驗證通過；必要的執行階段驗證完成 |
| 原生測試 | 經審查且有實質意義的判斷提示、實際執行的次數／成果、跳過的次數與限制 |
| 線上執行／診斷 | 實際受支援的執行佐證、必要的輸出／影響、失敗動作／平台錯誤 (若有的話) |
| 線上變更 | 保留的匯出／修訂版本、受防護的寫入結果、分開觀察到的執行階段行為 |
| 取消／重放 | 明確區分已要求／已接受／已觀察／未知狀態；不推斷新的執行識別碼 |
| 打包／部署 | 檢查過的封存／排除項目；經授權的必要條件；必要的部署後驗證 |
| 執行階段所有權 | 工作專屬的處理程序已停止並驗證，或明確保留並標註座標／所有權 |

明確說明遺漏的具體權限、相依性、資源、未執行的檢查、保留的
資源以及未確定的影響。請勿將已設定的身分識別稱為已授權、將已接受的
請求稱為已完成、將跳過的測試套件稱為通過，或將受阻的先決條件稱為已滿足。
