# 本機相依性與執行階段

在進行相依性安裝／檢查、執行階段健康檢查 (doctor) 或主機生命週期工作之前為強制必讀。
基準：`logicapp` 1.0.0b1。請先閱讀 `SKILL.md` 的規則。使用實際的專案根目錄、作業系統、
Shell、可用連接埠以及所有權佐證；`App` 與 7071 為範例座標。

## 必要條件與影響

在啟動或修復任何項目之前，先檢查現有組態、設定參考、接聽程式以及執行階段所有權。
請勿印出秘密值。執行本機主機可能會啟動輪詢／事件觸發程序，並使用本機認證
叫用真實服務。在啟動前先確立經授權的影響範圍與適當的非生產環境資源；
「本機」並不代表隔離。請勿將安裝相依性或啟動服務當作唯讀檢查的副作用。

## 安裝前先檢查

針對不存在的目的地，一般的 `dependency check` 可識別工具狀態。
一旦專案已存在，請使用具備專案感知能力的格式：

```azurecli
az logicapp dependency check --path App
```

檢查 Core Tools、Node.js、套件組合 (bundle)、.NET 以及 Azurite 的檢查發現。具備專案感知的檢查
能解析已設定的儲存體以及是否需要 Azurite；並非每項工具都是
每種作業所必需。本機 SDK 測試與線上主機具有不同的先決條件。

針對既有專案，在執行階段修復前先進行診斷：

```azurecli
az logicapp runtime doctor --path App --port 7071 --output json
```

Doctor 為唯讀操作：它不會安裝、下載、修復、啟動／停止服務、解密
設定，亦不會連線至雲端儲存體。它使用有邊界限制的本機回送探測以及本機專案／工具／
快取／所有權佐證。已停止的主機屬於選用的跳過探測項目，而非離線失敗。

| Doctor 結束代碼 | 意義與必要回應 |
|---|---|
| 0 | 無必要的受阻項目／未知事項；不代表商業邏輯正確或具備通用相容性 |
| 1 | 必要項目的失敗；檢查並解決實際的發現問題 |
| 2 | 必要項目的未知狀態，或 `--strict` 下的選用問題；保留診斷的不確定性 |

精確的工具／套件組合相容性在此基準中仍屬於必要未知事項；一個可正常回應的
專案也可能會結束於代碼 2。請勿僅因為相容性未知就重新安裝，亦不可將
結果轉化為已認證健康。在非零結束代碼時仍須保留結構化 stdout。
若適當，可使用本機 `--context` 替代路徑／連接埠；明確的內容環境不能與
`--path` 或 `--port` 合併使用。Doctor 不接受 `--local`。

## 僅安裝選取遺漏的相依性

僅安裝回報遺漏且為所要求作業所必需的種類：

```azurecli
az logicapp dependency install --kind core-tools --yes
az logicapp dependency install --kind node --yes
az logicapp dependency install --kind azurite --yes
az logicapp dependency install --kind bundle --yes
```

這些為替代方案，而非無條件執行的命令序列。若需要
多種種類，請重複指定 `--kind`。省略 `--kind` 會安裝所有可安裝的種類，這並非
預設程序。`--yes` 僅在安裝獲得授權後才適用。
檢查每個結束狀態，並在選取的安裝完成後重新執行具備專案感知的檢查。

限制事項：

- CLI 不會安裝 .NET SDK。回報所要求的遺漏 SDK，並使用客戶核准的
  安裝流程；請勿隱含執行遠端安裝程式。
- Azurite 需要 Node.js 22 或更新版本。在安裝 Azurite 之前先確認 Node/npm 可用。
- 受控相依性預設儲存於 `~/.azurelogicapps/dependencies`，與 VS Code
  工具共用；`LA_DEPENDENCIES_PATH` 或受支援的目標旗標可予以覆寫。
- 受控工具僅影響子處理程序環境，不影響全域 PATH。
- 遵循經核准的套件來源、Proxy 與網路政策。Azurite 安裝程式
  預設使用公用 npm 登錄檔，而非使用者設定的登錄檔。
  針對經授權的鏡像站台，請使用 `--kind azurite --source-url REGISTRY_URL`。
- `--source-url` 嚴格要求只能指定一種種類。自訂來源不會獲得相同的
  發佈者總和檢查碼驗證；必須獨立確認信任。絕不可停用 TLS。
- 需要時以 `--version` 固定單一選取的種類。請勿僅因為存在新版本
  就升級正常運作的工具。
- `dependency uninstall` 僅使用 `.logicapps-integrity.json` 移除記錄為
  CLI 所擁有的相依性。請先檢查共用情況並取得移除授權。

**檢查關卡：** 本項工作所需的每項相依性皆已可用，或已回報其具體受阻原因。
未知的相容性檢查發現不等於套件遺漏的發現。

## 啟動並驗證就緒狀態

檢查現有接聽程式後選取連接埠。請勿為了釋放連接埠而停止其他處理程序。
僅在確認其專案與允許的影響後，才重複使用合適的既有主機。

```azurecli
az logicapp runtime start --path App --port 7071 --background --ready-timeout 90
az logicapp runtime show --port 7071
```

必須同時滿足處於執行狀態 **且** `readiness.managementEndpointReachable: true`。
僅有開啟的連接埠或已記錄的處理程序是不夠的。若處於啟動中／失敗／未就緒，檢查
回報的 `logPath`，然後視情況重新執行 doctor。在就緒前請勿叫用工作流程。
記錄可能包含機密承載；在本機進行檢查並在共用前進行清理遮蔽。

當 `AzureWebJobsStorage` 解析為 `UseDevelopmentStorage=true` 時，啟動流程會管理位於
連接埠 10000-10002 的 Azurite 並重複使用既有模擬器。真實的儲存體組態不會
啟動 Azurite。僅在另一個獲授權的處理程序擁有其生命週期時，才使用 `--no-azurite`。
請勿手動編寫模擬器／執行階段狀態目錄。

檢查傳回的相依性記錄：

| Azurite 狀態 | 必要回應 |
|---|---|
| `started` | 記錄 CLI 所有權與相依主機 |
| `already-running` | 檢查 `startedByCli`；請勿從連接埠推斷所有權 |
| `port-conflict` | 識別非 Azurite 的接聽程式；停止啟動流程，而非停止無關的處理程序 |
| `missing` | 授權／安裝所需的 Azurite 相依性 |
| `not-started` | 檢查儲存體組態而不公開其數值 |
| `failed` | 檢查該相依性回報的 `logPath` |
| `skipped` | 確認為刻意由外部管理的模擬器生命週期 |

本機執行階段生命週期在適當情況下會遵循已儲存的本機內容環境連接埠；明確的路徑／連接埠
座標在自動化作業中更為安全。請勿在生命週期命令中加入僅限 API 的 `--local`。
這些命令不會管理雲端主機的啟動／關閉。

**檢查關卡：** 正確擁有／重複使用的主機、實際的管理就緒狀態、允許的觸發程序影響，
以及明確掌握相依性所有權。

## 停止前先進行診斷

在主機可連線時，使用從 `SKILL.md` 選取的強制性線上作業程序
收集必要的執行／動作佐證。僅有主控台輸出並非工作流程商業邏輯的
診斷。若不存在執行記錄或 Stateless 歷史記錄不可用，回報該事實
並使用受支援的回應／遙測佐證；請勿憑空捏造失敗動作。

## 僅停止所屬的處理程序

在所需的驗證、探索、執行與診斷完成之後：

```azurecli
az logicapp runtime stop --port 7071
az logicapp runtime show --port 7071
```

使用適用於該作業系統的處理程序／接聽程式檢查，確認工作所屬的主機已停止
且其接聽程式已關閉。若有新的接聽程式重複使用了該連接埠，識別它但不要
將其終止。請勿僅憑重複使用的連接埠就宣告原始主機仍處於存活狀態。

僅停止為此工作啟動的執行階段，除非明確獲授權關閉另一台主機。
若被要求讓主機保持執行，驗證其回應能力並回報專案、
連接埠與生命週期所有權，而非將其停止。

當 Azurite 是由 CLI 啟動時，只要有任何由 CLI 啟動的前台或
後台主機相依於它，它就會被保留。僅在最後一個相依主機停止後，其
10000-10002 接聽程式才應關閉。絕不可停止非由 CLI 啟動的模擬器。

CLI 處理程序所有權使用 PID 與建立身分識別。未知／已回收的身分識別與
無法解析的子系絕不可發送訊號。若清理工作仍處於擱置狀態，保留所有權
記錄並檢查回報的具體處理程序。僅使用經明確授權且經過身分識別
驗證的 PID；絕不可依可執行檔名稱進行強制終止，亦不可刪除記錄來繞過防護。
僅在審查所有權佐證後，才使用受支援的停止重試機制。

**檢查關卡：** 所有工作所屬的處理程序均已驗證停止，或已回報明確的保留／清理受阻原因。
共用與無關的服務均保持完好。
