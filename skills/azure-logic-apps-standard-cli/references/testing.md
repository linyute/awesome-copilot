# 原生工作流程測試

在執行 `test create`、`test plan`、`test run` 或 `test results show` 之前為強制必讀。
基準：`logicapp` 1.0.0b1。測試屬於選用／工作導向的操作，並非隱含的主機啟動、
相依性安裝、NuGet 還原、Azure 變更，亦無法取代整合檢查。

## 明確選取階段

| 命令 | 合約內容 |
|---|---|
| `test create` | 寫入新的原生 SDK／MSTest 原始碼；不進行還原或執行 |
| `test plan` | 具邊界限制的唯讀預先檢查／XML 檢查；不執行任何測試 |
| `test run` | 針對受信任的原生建構／測試進行明確執行，還原需分開選擇加入 (opt-in) |
| `test results show` | 檢查受支援且已儲存的 JSON；絕不重新執行測試或追蹤內嵌路徑 |

使用明確的 `--path App --workflow Orders`，否則使用具名／使用中的本機內容環境 (context)，
再否則使用目前目錄。明確的 `--path` 會繞過隱含的使用中內容環境；即使加上路徑，
明確具名的雲端內容環境也會遭到拒絕。本機規劃不需要 Azure 登入或
正在執行的主機。回報前的輸入／目標失敗不等於成功的規劃。

## 產生基本架構，隨後編寫實質判斷提示

首先檢查現有測試與輸出路徑。預設的基本架構輸出為所選主機專案
底下的 `Tests/Orders`；支援在專案內建立專屬測試目錄。
在明確選取時，外部專屬測試亦屬有效做法。

```azurecli
az logicapp test create --path App --workflow Orders
```

若目的地已存在，建立作業會予以拒絕，而非採用或覆寫它。多個
觸發程序需要明確指定 `--trigger`。相對 `--output-path` 會使用所選專案。
此基本架構包含原生專案／測試原始碼、觸發程序受測物、SDK 選取、NuGet
組態以及 Git 排除項目。它不會複製應用程式認證／設定或 SDK 二進位檔。

入門範本預設為被忽略 (ignored) 且不具結論性 (inconclusive)，**並非通過的商業邏輯測試**。
在同時移除 Ignore 屬性與 inconclusive 防護之前：

1. 針對實際的工作流程／觸發程序填入綜合觸發程序資料。
2. 使用受支援的 SDK 模擬 (mocks) 來模擬外部作業，包括必要的失敗路徑。
3. 針對所需的行為／動作輸出撰寫有實質意義的商業邏輯判斷提示。
4. 審查專案匯入、建構目標、套件來源與測試程式碼以確認允許的影響範圍。

基本架構會在建構時連結目前選取的工作流程。請勿僅為了取得通過結果而
移除有效的工作流程輸出、竄改預期的商業數值或削弱判斷提示。
僅工作流程處於 Succeeded 狀態並不代表具備商業邏輯涵蓋範圍。

## 僅規劃而不執行

```azurecli
az logicapp test plan --path App --workflow Orders --output json
```

規劃只會檢查本機編寫的輸入與常值參考；選用／預設基本架構的
`.csproj` 是 XML Metadata，而非經過評估的 MSBuild 或可執行的測試探索。它不會
安裝、還原、產生受測物、啟動主機或連線至雲端目標。

| Plan 結束代碼 | 意義 |
|---|---|
| 0 | 規劃已產生，非測試通過 |
| 1 | 編寫檢查發現問題 |
| 3 | 無效／不安全的本機輸入 |
| 4 | 在 `--strict` 下，原本成功的規劃後受阻的執行關卡 |
| 5 | 觀察到輸入漂移 (drift) |
| 6 | 報告發佈失敗 |

檢查 `notExecuted` 標記與發現項目。成功的規劃並不代表接受 SDK 條款或
授權執行。保留受支援歷史報告中所記錄的結束代碼政策。
報告預設僅輸出至 stdout。選用的 `--report-path` 需要已存在的父目錄；
覆寫規劃報告需要刻意指定 `--force`，但這不會授權任何 SDK 活動。

## 審查相依性、SDK 條款與專案信任

目前經過合格驗證的合約：Tests SDK **1.0.3**、引擎 **1.165.50**、MSTest **4.0.2**、
目標 **net8.0**、選定的 .NET **8** SDK。基本架構選取 **8.0.426** 搭配最新修補程式
向前復原 (roll-forward)。在既有專案中，目標 Framework 並不會自動選取 SDK。

**.NET 8 的支援終止日為 2026-11-10。** 請在執行時檢查生命週期與發行者
相容性。請勿無提示地升級固定的 SDK／引擎／執行器組合、移除選取
防護，或聲稱較新的工具鏈已經過合格驗證。若無可用的受支援且經核准組合，
回報原生測試執行受阻，並保持離線檢查可用。

審查發行者的
[SDK 1.0.3 授權條款](https://www.nuget.org/packages/Microsoft.Azure.Workflows.WebJobs.Tests.Extension/1.0.3/License)，
包含使用／轉散發／商業用途限制、資料收集與更新。
CLI 的 MIT 授權並不包含 SDK 的授權。需要時請向發行者／法務尋求
釐清；請勿將 SDK 二進位檔隨此 Skill 或產生的專案一同轉散發。

針對**每次呼叫**，在新增下列引數前均須取得授權：

- `--accept-sdk-terms`：呼叫者確認適用的 SDK 條款，非已儲存報告的授權。
- `--trust-project`：確認專案／匯入／目標／測試程式碼可以執行
  任意程式碼並連線至服務。
- `--restore`：分開授權透過經審查的來源解析套件。

請勿從啟動此 Skill、產生規劃、先前的執行、儲存的旗標、內容環境或
`--force` 推斷出這些權限。快取與模擬並非安全沙盒或被拒絕的
對外輸出 (egress)。針對不受信任的原生程式碼，請使用適當隔離的環境。

基本架構的 NuGet 組態會清除繼承的來源並選取官方摘要來源 (feed)。
在還原前，根據客戶核准的摘要來源／Proxy 政策調整／審查該組態；請勿
對所有使用者強制指定特定公司的 Proxy。適當情況下請使用明確的 `--nuget-config CONFIG_PATH`。
絕不可在還原失敗後繞過 TLS 或無提示地新增其他來源。
繼承自使用者的摘要來源／認證／Proxy 環境設定不會自動傳遞給
私有執行器；需要這些設定的鏡像來源必須透過受支援且經審查的
機制進行設定，而非假設其能正常運作。

現有的鎖定檔案使用鎖定還原；新的還原會產生鎖定檔案以供審查。
認可適當的 `packages.lock.json`，而非套件二進位檔。在未指定 `--restore` 的情況下，
建構／測試會使用 `--no-restore`；缺少相依性佐證屬於錯誤，而非下載的
許可。CLI 不會為了滿足此工作而安裝全域 SDK。

## 僅執行經審查的測試

唯有在取得上述核准後，才選擇所需的呼叫命令：

```azurecli
az logicapp test run --path App --workflow Orders --accept-sdk-terms --trust-project --restore --timeout 300
```

針對已審查且先前已還原的專案，省略 `--restore`。在包含 `App` 的目錄中，
於建立 `App\reports` 後，使用以下命令儲存全新的經過清理的報告：

```azurecli
az logicapp test run --path App --workflow Orders --accept-sdk-terms --trust-project --report-path reports/native.json --timeout 300
```

叫用範例時請使用主機作業系統的路徑分隔符號。使用 `--test-project` 選取
既有的自訂專案；無需僅為了執行測試而重新產生測試。
`--timeout` 限制原生步驟的時間 (1-3600 秒)；經過身分識別檢查的清理作業可能耗時更久。

| 路徑引數 | 解析基準 |
|---|---|
| 相對 create `--output-path`、plan/run `--report-path` | 選取的主機專案 |
| 明確的相對 `--test-project`、`--nuget-config` | Shell 目前目錄 |
| Results `--result-file`、`--workflow-file` | Shell 目前目錄 |

當這些不同的基準可能造成混淆時，請使用絕對路徑。報告父目錄必須
存在；原生報告目的地必須為新檔案。例如，在建立 `App\reports` 目錄後，
`--path App --report-path reports/native.json` 會寫入
`App\reports\native.json`。若改用 `--report-path native.json` 則會寫入 `App\native.json`，
而非 reports 目錄中的檔案。結果檢查時必須指定相對於 Shell 工作目錄
(而非所選專案) 的相同已儲存檔案。

## 解讀結果而不誇大涵蓋範圍

| Run 結束代碼 | 意義 |
|---|---|
| 0 | 原生測試通過且至少執行了一項測試；檢查跳過的數量與判斷提示 |
| 1 | 原生測試／判斷提示失敗 |
| 2 | 工具鏈、相依性、還原／建構、執行器或結果錯誤 |
| 3 | 無效／不安全的本機輸入 |
| 4 | 缺少條款／專案信任確認；未進行原生執行 |
| 5 | 觀察到所選輸入發生漂移 |
| 6 | 報告發佈失敗；重試前檢查目的地 |
| 7 | 執行測試數為零，包含完全被跳過的基本架構；非通過 |
| 8 | 原生執行逾時截止；無完整判定結論 |
| 9 | 安全處理程序清理未完成；保留所有權收據 |
| 130 | 中斷；無完整判定結論 |

原生計數並不能證明任意 C# 程式碼叫用了 SDK、執行了所選的
工作流程或涵蓋了有用的行為。保留 `notAttested` 的工作流程／商業邏輯涵蓋範圍
以及 `notProvided` 隔離標記；以經過審查的判斷提示來補充計數數據。

原生的 stdout/stderr 不會被 CLI 直接輸出。原始 TRX 會保留在專屬測試目錄的
`.logicapp-test-state` 執行儲存區中，並可能包含受測物、輸出、路徑以及
失敗詳細資訊。請保護它；請勿將其當作清理後的報告進行共用。
選擇退出 CLI 遙測並不代表 SDK 遙測已被停用。

在包含 `App` 的相同目錄中，檢查該儲存且清理後的報告與選取的工作流程：

```azurecli
az logicapp test results show --result-file App/reports/native.json --workflow-file App/Orders/workflow.json
```

依路徑表選取實際檔案。結果檢查僅接受封閉受支援的
預先檢查／原生 JSON，不接受原始 SDK/TRX。它不會追蹤報告內嵌的路徑、
重新執行測試，亦不會驗證作者身分。檢查結束代碼為 0 代表讀取成功；記錄的
成果／計數屬於歷史數據。選取的工作流程位元組比較能偵測漂移，但非新的
執行或經證實的涵蓋範圍。

## 失敗與清理邊界

SDK 1.0.3／引擎 1.165.50 對於某些有效的非空型別最頂層工作流程輸出，
存在已記錄的 `InvalidCastException`。請勿刪除輸出、修補二進位檔或變更
工作流程語意來隱藏此問題。回報實際失敗的測試／SDK 限制，並尋求個別
合格的發行者修復版本。動作輸出判斷提示並非通用的因應措施。

若清理作業無法安全完成，保留處理程序收據與所有權佐證。
當此類收據殘留時 (包括格式錯誤的收據)，後續的執行會拒絕新工作。
請勿刪除收據或依名稱終止處理程序來解除執行封鎖。請明確檢查／協調
所有權；回報未解決的清理工作。僅憑舊的已完成報告並不能授與
停止任何項目的許可。

將原生測試／狀態保持在專屬目錄中。請勿將其與主機／工作流程
執行階段內容放在同個位置。打包會排除經過驗證的專屬原生測試內容與原始 TRX，
但任意受信任的程式碼可能會寫入其他位置：請獨立檢查套件內容。

**檢查關卡：** 所需的原生判斷提示已實際執行、回報了計數／成果／限制、
保留了經核准的來源／條款／信任邊界、排除了機密產物，且無
隱藏的清理或相依性受阻問題。
