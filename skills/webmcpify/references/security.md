# 安全性檢核清單

在兩個時間點套用：**在
資訊清單核准
閘門之前**，
以及**在驗證之後**。

## 一段話的威脅模型

任何具有主機權限的
Chrome
擴充功能、被注入的腳本或在相同來源中執行的惡意軟體都可以列舉並呼叫
WebMCP
工具。工具處理常式必須將每個輸入視為不可信，
並強制執行與任何外部呼叫端相同的授權檢查。

## 測試載具存取邊界

威脅模型描述了消費者在瀏覽器中能執行的操作；



測試載具在隔離的上下文與
專用設定檔中執行，
絕不重複使用使用者的日常認證資訊。

## 檢核清單

**範圍詞彙**
- [ ]
身分/租戶界限在工具範圍中得到尊重。

- [ ]
敏感管理工具不會暴露給非特權使用者。

**信任邊界** - [
] 每個
`execute()`
處理常式都會驗證輸入結構與類型。
- [ ]
不允許透過工具參數進行路徑遍歷或未經驗證的重定向。

**人機協同
(Human-in-the-loop)**
- [ ]
異動型操作沒有
`toolautosubmit`。
- [ ]
高風險操作要求明確的使
用者互動或確認對話方塊。

**生產副作
用（驗證）**
- [ ]
所有驗證執行皆使用
測試資料或隔離環境。
- [ ]
任何即時生產異動皆已取
得明確核准並在事後清理。


**誠實與
提示**
- [
]
說明文字忠實
反映工具功能，
沒有欺騙性提示。
- [
]
錯誤訊息清楚
描述失敗原因，
不外洩內部秘密。

**隱私** - [ ]
結構描述不會請求超出完成工作所需以外的資料。
- [ ]
記錄與遙測中不會包含 PII 或憑證。

**包容性與
遏制**
- [ ]
工具僅在
HTTPS/安
全上下文下執行。
- [ ]
透過適當的
Permissio
ns-Policy
限制
iframe
中的工具存取。
