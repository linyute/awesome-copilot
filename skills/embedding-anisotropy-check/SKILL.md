# 嵌入向量各向異性檢查 (Embedding anisotropy check)

嵌入向量之間的原始餘弦值極少以零為中心。大多數句子編碼器與隱藏狀態層會將
每個向量置於某個共享方向附近，因此兩個不相關的輸入可能得到 0.6、0.9 或 0.99 的分數。此時，0.9 的配對
本身並不能作為任何事情的證據，而兩種條件之間 0.01 的差距可能是全部的訊號，也可能完全沒有訊號。
此技能讓每一個此類比較都帶有其自身的基準底線。

## 代理人如何觸發此技能

代理人在此處不需要進行向量化。無論向量是由誰產生的，此技能在代理人即將回報餘弦數值時套用：

- **代理人撰寫了評估程式碼。** 類似「為我們的索引撰寫檢索評估」或「檢查此編碼器的 4 位元匯出是否仍與 bf16 相符」的請求，
  最終會產生一個印出平均餘弦值的指令檔。在代理人斷言「0.91，匯出沒問題」之前，它會將相同模型的不相關配對透過指令檔執行，
  並在配對數值旁回報基準底線。
- **工作區中已存在向量。** 例如 `embeddings.npy`、在已儲存的隱藏狀態上評估的探針或適配器、向量存放庫傾印檔案。
  當被問及「這兩層是否編碼了相同的內容」或「微調是否改變了表示法」時，代理人會在回答之前載入陣列並執行檢查。
  - **正在撰寫論點。** 代理人正在起草 README、PR 說明或結果表格，其中宣稱相似度很高、說明兩種條件一致，
  或稱微小差異為無效果。該句子中的數字即為觸發點。

## 何時使用此技能

- 單一模型在兩種精度（bf16 對比 4 位元）、兩個執行階段或兩個鄰近層下的相同輸入，它們共享同一個坐標空間。
- 在單一嵌入空間內的查詢與段落、影像與說明文字，或任何其他成對評估。
- 任何宣稱相似度很高、兩種條件一致或微小差異為無效果的語句。

不適用於各自獨立訓練的原樣模型。單一模型空間的旋轉會保持其幾何形狀，但會改變
相對於另一個模型的每個餘弦值，且中心化並不會對齊這兩個基底。請先擬合明確的對應關係，
例如在成對列的訓練分割上進行正交 Procrustes 分析，然後比較對應後的資料列；或者改為比較每個模型
自身在空間內的相似度。

## 步驟程序

1. 將比較的資料列儲存為形狀為 `(n, d)` 的兩個 `.npy` 陣列，A 的第 `i` 列與 B 的第 `i` 列配對。
2. 選擇平均值的來源。最佳來源是來自與比較資料列相同領域、模型與模態的訓練分割。
   在其他領域上擬合的平均值會導致中心化偏差：它可能會保留部分共享方向、
   移除過多方向，或加入其自身的特定方向，而留下的部分看起來就像是領域差異所造成的影響。
3. 執行隨附的指令檔：

   ```bash
   python scripts/anisotropy_check.py A.npy B.npy --fit-a trainA.npy --fit-b trainB.npy
   ```

   當 A 與 B 來自同一個模型與同一個母體時，傳入 `--shared`，以便兩側都透過單一平均值進行中心化。
   若沒有 `--fit-a` 與 `--fit-b`，平均值會直接依據被比較的資料列本身進行擬合，且輸出的 `means`
   欄位會針對每一側說明其平均值取自哪些資料列。
4. 並列回報：每一側的各向異性 (anisotropy)、中心化前配對相對於基準底線的比較、中心化後配對相對於基準底線的比較，
   以及 `partner_ranked_first` 相對於其機率值 `1/n` 的表現。

## 解讀輸出結果

- `anisotropy` 是單側不同列之間的平均餘弦值。對於較大的 `n`，它接近單位列平均值的平方長度，
  因此它測量了這些列在多大程度上共享一個共同方向，而這正是中心化所要消除的。
  它並不能偵測出所有偏離各向同性的情況：沿單一軸雙向分佈的列得分接近 0，但仍會產生 +1 和 -1 的原始餘弦值。
  接近 0 的數值表示單側內部幾乎沒有可消除的平均方向，並不代表原始餘弦值可以在沒有基準底線的情況下單獨解讀。
  高於約 0.3 時，該側內的列會強烈聚集在平均方向周圍（指令檔會加入警告訊息）；請檢查 `raw.floor` 以觀察該方向
  在兩側之間共享的程度，並同時回報原始與中心化的配對與基準底線讀數（中心化會改變評分函式，
  無法取代對使用原始餘弦進行搜尋之索引的評估）。
- `raw.floor` 是在此比較中非相關配對的得分。配對餘弦值僅在與此基準底線的差距中具有意義。
- `centred.gap_over_floor_sd` 與 `centred.cohens_d` 表示配對項目是否能與非相關項目區分開來。
  當非相關配對的得分全部相同時，基準底線沒有離散度，且 `gap_over_floor_sd` 為 `null`：差距無法
  以基準底線標準差表示，此時應直接讀取單純的 `gap` 數值。
- `partner_ranked_first` 是相同配對的檢索視圖。中心化可能會使排名向任一方向移動，因此請同時回報兩種方式的結果，
  而不要假設效果會直接轉移。

## 搭配數值應遵循的規則

- 計算跨種子或跨項目的帶正負號差異的平均值，然後取其絕對值。對絕對差異取平均值會產生向上偏差，
  且當差距相對於其雜訊較小時，該偏差最為顯著。
- 提供差距及其離散度，以及該測試所能偵測到的最小效應。檢定力不足的比較不等於推翻反駁，
  報告中應明確說明屬於兩者中的哪一種情況。
- 在每個結果旁附上來自同一個比較的基準底線。從另一次執行、其他模型或不同領域複製過來的基準底線
  無法修正當前的比較。

## 範例

在 `mteb/scifact` 語料庫的前 100 篇文件上使用 bge-small-en-v1.5，每篇文件均在中間句子邊界處分割為前半部與後半部，
以單一摘要的前後半部作為配對項目，並由兩側共享單一平均值 (`--shared`)。`scripts/example_scifact_halves.py` 重建了此過程：
它將語料庫固定在修訂版本 `cf10ab6`，模型固定在 `5c38ec7`，宣告了句子分割方式，且除了 numpy 之外還需要 `datasets`
與 `sentence-transformers`。在 datasets 5.0.1、sentence-transformers 6.0.1、torch 2.13.0 與 numpy 2.5.1 環境下，
其產生的結果如下（四捨五入至小數點後四位）：

| | 配對項目 (matched) | 基準底線 (非相關半部) | 相對於基準底線標準差的差距 |
| --- | ---: | ---: | ---: |
| 原始餘弦值 | 0.8636 | 0.6024 | 4.38 |
| 中心化餘弦值 | 0.6487 | -0.0131 | 5.87 |

各向異性 (anisotropy) 分別為 0.5956 與 0.6148，且此處兩側共享同一個空間，因此在中心化之前，
非相關半部就已經達到了配對半部得分的 70%。兩個空間都能將配對半部與非相關半部分開（原始基準底線標準差為 4.38，
中心化後為 5.87），並在大部分摘要中將其夥伴排在第一位（100 篇中分別佔 97 篇與 98 篇），而中心化則消除了
0.6024 的基準線偏移量。
