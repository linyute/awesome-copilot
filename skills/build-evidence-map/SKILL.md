# 建構證據圖 (Build Evidence Map)

將一個有爭議的問題轉化為可攜式的決策產物，展示支援
當前立場的內容、反對它的內容以及仍然未知的內容。
請勿使用圖形來裝飾未經證實來源的答案。

對於簡單的事實主張或一般事實查核請求，請改用
如 `doublecheck` 之類的驗證工作流程。當證據、
中間主張、權衡取捨和缺失事實之間的關聯至關重要時，請使用此技能。

## 工作流程

1. **界定一個決策。** 撰寫一個可證偽的問題和一個臨時
   立場。縮小問題範圍，直到讀者能夠識別該圖正在測試什麼行動或
   信念。
2. **收集有界的來源區域。** 優先選擇直接觀察與主要
   來源。記錄 URL 或本機絕對路徑、發佈者、發佈日期、
   檢索日期、章節/頁面/行/時間戳記定位器，以及簡短的可檢查
   節錄。當來源品質存在爭議時，閱讀 [references/evidence-ladder.md](references/evidence-ladder.md)。
3. **將推理原子化。** 僅建立四種節點類型：
   - `position`：單一目前結論；
   - `claim`：中間命題；
   - `evidence`：一個來源區域的忠實陳述；
   - `unknown`：可能改變結論的特定缺失事實。
4. **為每條邊線設定類型。** 使用 `supports`、`contradicts`、`qualifies` 或
   `missing`。新增白話附註，解釋來源節點為何與
   目標相關。主題相似性不代表支援。不同的範圍、日期或
   母體不會自動構成矛盾。
5. **保留反面證據。** 不要因為臨時結論在反面證據下仍然成立而刪除該反面證據。使用
   `qualifies` 邊線表示範圍差異。
6. **結構化表達不確定性。** 不要捏造信賴度百分比。
   新增 `unknown`、縮小立場範圍或修飾主張。
7. **撰寫帶有 `.doubt.json` 後置詞的 UTF-8 JSON**。遵循
   [references/map-schema.md](references/map-schema.md)。保持 ID 簡短、
   穩定且具語意。
8. **安全失敗 (Fail-closed) 驗證。** 解析
   `scripts/validate.mjs` 相對於此 `SKILL.md`，然後使用 Node.js
   18 或更高版本執行它：

   ```bash
   node <skill-directory>/scripts/validate.mjs decision.doubt.json
   ```

   隨附的驗證器僅使用 Node.js 內建功能，不需要 npm 或
   網路存取。在回報成功之前修復每個調查結果。僅在指令結束代碼為
   `0` 並印出 `VALID` 後接 64 字元的收據時，才表示該圖
   有效。檔案雜湊、節點計數、JSON 解析或手動結構描述審查不是
   Doubt 收據。如果確定性驗證無法執行，請回報
   該阻礙，而不是捏造成功。

   僅在使用者已安裝 `doubt-ai@0.8.0` 時呈現已驗證的圖；
   不要隱式安裝或執行遠端套件：

   ```bash
   doubt map decision.doubt.json --out decision.html
   ```
9. **僅在有明確網路權限的情況下驗證來源快照。** 以下
   指令會檢索每個記錄的 HTTP(S) 來源，若無法匹配
   節錄則安全失敗：

   ```bash
   doubt verify decision.doubt.json \
     --out decision.verified.doubt.json
   ```

   切勿隱式執行此指令。本機檔案驗證不使用網路。
   不要手動撰寫 `verification` 物件或隱藏不匹配的情況。
10. **檢查交付成果。** 確認問題、結論、
    反面證據、未知事項、邊線附註與確切來源區域保持
    可讀。將 JSON 視為規範的可編輯產物；HTML 是
    可分享的檢視表。

## 品質關卡

完成的圖必須滿足以下所有條件：

- 恰好一個 `position` 具有傳入的推理；
- 每個證據節點均指名一個來源並參與一條邊線；
- 每個來源均被使用且具有日期、有界的定位器和實質性的
  節錄；
- 每個非立場節點都有一條通往立場的有向路徑；
- 推理圖沒有重複的邊線或有向循環；
- 當來源集合包含反面或限制修飾證據時，該證據必須存在；
- 每個會改變決策的缺口都是一個明確的 `unknown` 節點；
- 每個邊線附註都解釋了支援、矛盾、限制修飾或缺失；
- 結論不超出證據範圍。

## 交付結果

回報：

- 用一句話說明當前立場；
- 最強的反面證據或限制修飾；
- 最重要的未解決未知事項；
- 規範 JSON 和任何轉譯之 HTML 的路徑；
- 確定性驗證和明確的來源驗證是否已執行。

切勿將結構上有效的圖描述為被證明為真。驗證建立了
可追溯性與圖的完整性；來源品質與推論品質仍
需要人工審查。
