# 開啟工作桌 (Open a Desk)

在工作坊中建立具有標準結構的新工作桌。

## 何時使用

- 操作員想要啟動新的工作串流
- 送來了不屬於任何現有工作桌的工作
- 某個主題需要自己的框架（自己的歷史、自己的先驗資訊）

## 它建立了什麼

給定工作坊目錄與工作桌名稱，建立：

```
desks/<desk-name>/
  journal.md       # 持久記憶 — 在開始時讀取，在結束時寫入
  .signals/        # 結構化訊號輸出 (JSON) — 儀表板會讀取此內容
```

## 如何使用

1. **選擇名稱。** 簡短、具描述性、kebab-case。該名稱是
   操作員和其他工作桌參照此工作桌的方式。
   範例：`security-scan`、`api-review`、`ops`、`cloud-workshop`

2. **檢查是否已存在。** 如果 `desks/<desk-name>/` 已經
   包含 `journal.md`，則該工作桌已在運作中 — **請勿覆寫它。**
   相反地，恢復它：讀取日誌並從上次中斷處繼續。
   如果操作員明確想要全新開始，他們必須先將現有工作桌
   重新命名或封存。

3. **建立結構。** 建立目錄、初始日誌與訊號資料夾：

   ```
   desks/<desk-name>/journal.md
   desks/<desk-name>/.signals/
   ```

4. **撰寫第一篇日誌條目。** 日誌開頭包含：
   - 此工作桌的用途（其重點/目的）
   - 它涵蓋哪些存放庫或工作（若適用）
   - 第一場會話所需的任何初始上下文

5. **宣布它。** 告訴操作員建立了什麼以及工作桌的
   重點是什麼。

## 會話導向

此技能初始化儲存區 — 它不會啟動會話。
當 Copilot 會話參照其目錄時，工作桌即變為作用中狀態。
會話工作流程：

1. 操作員（或 TA）啟動會話並說「在 `<desk-name>` 工作桌就座」
2. 會話讀取 `desks/<desk-name>/journal.md` 以載入先驗資訊
3. 進行工作 — 會話使用 `signal-write` 發出訊號，
   並在結束時使用 `desk-journal` 保留狀態
4. 下一個會話從步驟 2 重複進行

工作桌身分來自於讀取哪本日誌，而非來自持續執行的處理程序。
工作桌在*狀態*上是長期執行的（日誌會向前傳遞），
而不是在*執行階段*上（每個會話都是獨立的）。

## 日誌格式

```markdown
# <Desk Name> — Journal

## <date> — Desk opened
- **Purpose:** <what this desk focuses on>
- **Scope:** <repos, areas, or work this desk covers>
- **Next step:** <what the first session should do>
```

## 原則

- 工作桌是同儕，不是子代理。它與其他工作桌具有
  平等的地位可持有不同意見。
- 日誌是記憶。沒有它，下一個會話就會盲目開始。
  寫入足夠的內容，讓從零開始的人找到前進方向。
- 一個工作桌，一個重點。如果範圍過於寬泛，請開啟兩個工作桌。
  每個工作桌的價值來自於其特定的框架 — 稀釋框架就會
  失去價值。
