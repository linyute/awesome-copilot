# 自我批判循環

完成初步分析後，在交付報告前必須完成**強制的第二輪**。

## 通用檢核

1. **證據檢核**：每一項發現都必須引用已驗證的參考（`file:line`、元件、架構元素或 CVE ID）。移除沒有支援證據的發現事項。
2. **涵蓋範圍檢核**：驗證你已評估所有必要的類別與階段。對無問題的類別寫上"未偵測到"。不得省略無問題的類別。
3. **修復檢核**：為每項 Critical 與 High 發現提供具體、可執行的修復方案。不得提供籠統的建議。

## 領域檢核

### SAST/SCA

1. **污點追蹤完整性**：驗證你已將每個發現的進入點從來源追蹤至匯點（sink）。
2. **Manifest 涵蓋範圍**：驗證你已稽核所有發現的相依性 manifest。
3. **證據完整性**：每項 SAST 發現都須引用已驗證的 `file:line` 參考與污點追蹤。每項 SCA 發現都須引用已驗證的 CVE ID 與受影響的版本範圍。
4. **缺陷類別完整性**：確認你已評估所有缺陷類別。對無問題的類別寫上"未偵測到實例"。不得省略無問題的類別。
5. **政策一致性**：驗證 PASS 或 FAIL 的政策判決與嚴重程度計數及政策門檻規則相符。

### 威脅建模

1. **STRIDE 完整性**：驗證你已對每個信任邊界與資料流評估全部六個 STRIDE 類別（S/T/R/I/D/E）。
2. **信任邊界稽核**：驗證每個已識別的信任邊界至少有一條已評估的資料流穿越它。
