# 自我反思品質門檻

完成分析後，依領域類別以 1–10 分制為輸出評分。

**門檻**：每個類別都須評 **≥ 8** 分才通過。若任何類別評 < 8 分，在交付報告前先解決缺口（最多 2 次返工迭代）。

## 核心評分準則（通用）

| 類別           | 9–10 分                                                                                  | 7–8 分                                                             | 5–6 分                                                           | 1–4 分                                                       |
| ------------------ | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------- |
| **完整性**   | 所有階段、類別、邊界與檢核清單皆經評估，並附有明確證據         | 略有不完整，但不影響風險概況                   | 涵蓋範圍有明顯缺口；整個章節遭省略                | 僅走過場；主要章節缺失                        |
| **準確性**       | 精確的 file:line 參考、已確認的 CVE ID、已驗證的污點流、正確的 CWE 對應 | 輕微的版本模糊或間接引用；核心發現正確 | 看似合理但細節未驗證或對應可疑的發現 | 捏造的參考、錯誤的 CWE 對應或幻覺（hallucinated）CVE |
| **可執行性**  | 具體的修復程式碼、精確的套件升級目標、逐步指引             | 方向明確，但需人工調整                         | 沒有程式碼或版本目標的高層建議                   | 泛泛而談的套話（"清理輸入"、"保持套件更新"） |
| **一致性**    | 風險評級與證據相符、框架判決與發現事項一致、格式統一     | 輕微的格式或分類不一致                          | 嚴重程度評級與衝擊描述相互矛盾                  | 發現事項相互矛盾或判決不相容                 |
| **證據嚴謹度** | 每一項主張皆有程式碼、manifest、追蹤或威脅模型元素支援                        | 多數發現有支援；部分次要主張缺少引用            | 未附程式碼引用的斷言                              | 完全沒有程式碼或 manifest 佐证的推測性發現         |

## 評分門檻

| 最終得分                  | 動作                                                                    |
| ---------------------------- | ------------------------------------------------------------------------- |
| 所有類別 ≥ 8           | **PASS（通過）** — 進入最終交付                                      |
| 任何類別 < 8（第 1 次） | **REWORK（返工）** — 處理缺失並重新評分                            |
| 任何類別 < 8（第 2 次） | **REWORK（返工）** — 最後一次嘗試解決缺口                                |
| 任何類別 < 8（第 3 次） | **FLAG & DELIVER（標記並交付）** — 交付並向使用者明確揭露品質缺口 |

## 領域特定準則

### SAST/SCA

| 類別          | 問題                                                                               | 門檻 |
| ----------------- | -------------------------------------------------------------------------------------- | :-------: |
| **完整性**  | 是否評估了所有 SAST 缺陷類別與 SCA 生態系統？                          |    ≥ 8    |
| **準確性**      | 發現事項是否由具體的污點追蹤與已驗證的 CVE ID 支援？                  |    ≥ 8    |
| **可執行性** | 每項 Critical 與 High 發現是否都有具體的程式碼修復或升級步驟？          |    ≥ 8    |
| **一致性**   | 嚴重程度評級、CWE 對應與政策判決在整個報告中是否一致？  |    ≥ 8    |
| **涵蓋範圍**      | 是否已將所有進入點從來源追蹤至匯點，並稽核所有相依性 manifest？ |    ≥ 8    |

### 威脅建模與程式碼檢視

| 類別         | 問題                                                                            | 門檻 |
| ---------------- | ----------------------------------------------------------------------------------- | :-------: |
| **完整性** | 是否對每個信任邊界與資料流評估了全部六個 STRIDE 類別？   |    ≥ 8    |
| **涵蓋範圍**     | 是否已將所有進入點、信任邊界與資料流從來源追蹤至匯點？ |    ≥ 8    |
