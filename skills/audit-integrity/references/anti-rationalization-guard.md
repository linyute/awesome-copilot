# 反合理化防護

以下合理化說法**絕非**跳過、省略或降級發現事項的合法理由：

## 通用合理化說法

| 若你認為……                            | 必要回應                                                                                                            |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| "初步掃描未發現問題或威脅" | 在得出無問題的結論前，必須對所有類別進行系統性評估。擴大範圍並完成完整矩陣。 |
| "看起來沒問題，跳過深入分析"      | "看起來沒問題"不是證據。證據是程式碼追蹤、架構引用或規則比對。執行檢查。                    |
| "實際上的風險可能較低"   | 風險等級以衝擊乘以可能性計算。任何降級都須以明確證據證明合理。                         |
| "這是誤報（false positive）"                 | 將該發現標記為可能的誤報，但仍須納入。不得悄悄壓抑發現事項。文件化其理由。    |
| "這超出範圍"                    | 明確說明原因，並引用已声明的範圍或評估邊界。                                          |
| "這裡不需要任何控制或緩解措施"   | 明確寫出"未識別出缺口——理由：[X]"。沉默不等於保證。                                              |

## SAST/SCA

| 若你認為……                          | 必要回應                                                                                          |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| "SCA 的 CVE 在此無法被利用"        | 附上已文件化的情境說明後納入該 CVE。不得悄悄壓抑。                                   |
| "這個階段可以跳過"              | 所有階段皆為必要。對於因缺少輸入而無法完成的階段，加以文件化。                |
| "就情境而語，嚴重程度應較低" | 嚴重程度以 CVSS 或可利用性為基準。任何降級都須以明確證據證明合理。不得壓抑。 |

## 威脅建模

| 若你認為……                                | 必要回應                                                                                       |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| "這個威脅已被架構化解" | 文件化具體的補償性控制（compensating control），並驗證其已落實。不得假設。             |
| "此類別在此沒有適用的威脅" | 明確寫出"未識別出適用的威脅——理由：[X]"。不得悄悄省略類別。   |
| "在此橫向移動不太可能"            | 文件化可防止樞紐攻擊（pivoting）的具體架構控制，並驗證其已落實。    |
| "這個威脅角色不會以此為目標"      | 文件化排除該威脅角色的依據。你必須始終考量內部威脅與供應鏈攻擊者。 |
