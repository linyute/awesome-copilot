# macOS 27 Golden Gate 視覺語法

## Golden Gate 的改變

Golden Gate 完善了 macOS 26 引進的 Liquid Glass 系統。這不是將所有表面都做成半透明的許可。

Apple 的 2026 年指引描述：

- 透過對複雜內容更好的擴散來提升易讀性
- 更暗的材質邊緣與更明亮的高亮以營造深度與區隔
- 使用者色調控制，從非常清晰到完全著色
- 自動適應「減少透明度」與「增加對比」
- 側邊欄延伸至視窗邊緣
- 內容適當延伸至側邊欄後方流動
- 半粗體側邊欄選取文字
- 當浮動標題文字需要區隔時的硬捲動邊緣效果
- 採用 Liquid Glass 的側邊欄上方具外框的工具列項目
- 更緊湊的 macOS 視窗圓角
- 回應指標點擊的互動式自訂玻璃

這些是對原生結構的改進。結構始終是第一道設計決策。

## 單一視窗構圖

將生產力視窗視為一個構圖：

`[ 全高側邊欄 ] | [ 主要內容 ] | [ 選用檢視檢查器 ]`

標題列與工具列座落在視窗框架中，或與內容邊緣整合。各窗格可以使用不同的系統材質，但不需要在視窗內套用圓角包裝器。

使用：

- 窗格間單一共享邊界
- 原生分割檢視行為
- 連續的內容平面
- 需要時使用系統分隔線或極細線
- 使用間距與排版進行局部群組
- 選取填滿以表示選取
- 暫態表面僅用於暫態工作

避免：

- 整個側邊欄周圍帶有圓角矩形
- 每個側邊欄區段周圍又有圓角矩形
- 圓角主外殼內的內容卡片
- 當表單或表格為主要內容時卻永久浮動
- 使用重複陰影來解釋層級

## 容器預算

從零卡片預算開始。

僅在下列情況下，帶框容器才合理：

- 可獨立移動、關閉、重複使用或重新排序。
- 代表集合中邊界至關重要的獨立物件。
- 為暫態性質，例如彈出視窗、功能表、工作表、警示或浮動公用程式。
- 其邊界傳達拖曳目標、焦點、選取、驗證或預覽。
- 原生平台元件本身提供邊界。

容器不能僅因下列原因而變得合理：

- 該區段需要層級或內距
- 網頁儀表板會使用卡片
- 玻璃在桌布上看起來很吸引人
- 相鄰內容具有圓角

若需要群組，請嘗試以下順序：

1. 對齊
2. 間距
3. 區段標題
4. 語意背景變更
5. 分隔線或分隔元件
6. 原生分組元件
7. 僅在邊界保持有意義時才使用帶框容器

## 玻璃預算

玻璃是一種階層與互動材質，不是佈景主題。

強烈建議項目：

- 原生工具列項目群組
- 搜尋與精簡指令欄位
- 系統側邊欄與檢查器材質
- 媒體或畫布上方的精簡浮動控制項
- 彈出視窗、功能表、工作表與警示
- 其移動或回應能受益於真實 Liquid Glass 的小型自訂控制項

不建議項目：

- 長篇閱讀區域
- 密集表格
- 每個設定區段
- 每個側邊欄群組
- 每個資料列或資料儲存格
- 整個內容背景
- 裝飾性內部視窗外殼

在一個玻璃圖層即可滿足時使用單一玻璃圖層。不要為了製造對比而層疊玻璃。若對比不足，請簡化背景、使用系統邊緣處理或穩定內容表面。

## 側邊欄語法

- 使用全高前置導覽窗格。
- 將來源清單層級用於位置、集合、篩選條件、帳號或最上層目的地。
- 將多數層級維持在一個或兩個可見層級。
- 使用簡潔的群組標籤、SF Symbols 與原生資料列大小。
- 使用單一選取高亮；讓未選取的資料列保持安靜。
- 讓系統強調色傳達選取狀態與選取的圖示。
- 允許調整大小與在窄寬度時適當收合。
- 提供標準顯示/隱藏指令與鍵盤行為。
- 不要將關鍵動作置於底部邊緣。
- 不要將側邊欄內縮至圓角卡片中。
- 不要將每個側邊欄群組變成迷你面板。

官方套件展示了共用窗格上的多種來源清單排列。已選取資料列背景是一種狀態處理，不是包裝每個資料列的範本。

## 工具列語法

- 將導覽與側邊欄控制項置於前緣，接著是標題。
- 將常用、實用、可自訂的控制項置於中間。
- 將重要的持久性動作、檢查器控制項、搜尋與溢位置於後緣。
- 依工作與目標分組，而非單純視覺對稱。
- 將相異群組減至最少；Apple 的 HIG 建議以最多三個為目標。
- 當視窗變窄時讓系統管理溢位。
- 在適當時透過功能表列提供指令。
- 優先使用具高辨識度且無裝飾邊框的符號。
- 將文字標籤與僅有符號的動作群組分開。
- 最多使用一個顯著的主要動作。
- 當內容經過工具列下方時，使用原生捲動邊緣處理。

不要在內容中新增自訂全寬橫幅、每個圖示周圍加上藥丸形狀，或永久性玻璃指令列。

## 內容語法

主要內容應比導覽與指令更扁平、更安靜。

### 清單與表格

- 使用原生 `List`、`Table`、`NSTableView` 或 `NSOutlineView`。
- 使用資料列、欄、標頭、交替背景、展開揭示、縮排與選取。
- 讓表格佔據內容窗格。
- 避免在表格周圍使用玻璃或圓角包裝器。
- 不要將每個資料列做成卡片。
- 僅在能改善瀏覽時才使用分隔線。

### 表單與設定

- 使用原生 `Form`、設定場景、標籤、控制項與區段標題。
- 首先依間距與標題分組。
- 將群組方塊保留給確實需要封閉的關聯。
- 避免為普通偏好設定類別堆疊圓角面板。
- 保持控制項對齊與標籤欄一致。

### 編輯器、文件、畫布與媒體

- 讓文件或畫布擁有內容平面。
- 透過原生行為將適當的視覺內容延伸到側邊欄或檢查器下方。
- 保持浮動控制項精簡且疏朗。
- 不要將畫布置於另一個裝飾性卡片內。

### 檢查器

- 將檢查器視為相鄰的從屬窗格。
- 一致對齊控制項與區段。
- 使用原生展開揭示與分隔線。
- 除非確實可移動或為暫態，否則不要將其做成永久浮動卡片。

## 圓角與邊界

更一致的圓角並不意味著每個區段都要圓角。

- 保留視窗圓角、工作表、彈出視窗、功能表、浮動公用程式與原生控制項。
- 當真實表面巢狀於容器邊緣附近時，保留同心圓角關係。
- 優先使用直線共享窗格分隔線，而非兩個相鄰的圓角矩形。
- 將細語意線用於表格欄、窗格分隔或捲動邊緣對比。
- 當材質或位置已建立邊界時，避免加上筆畫邊框。
- 不要為原生元件發明固定半徑。

## 色彩與排版

- 使用語意系統顏色，而非硬式編碼的淺色與深色數值。
- 將系統強調色用於選取、進度與少數關鍵動作。
- 不要用強調色為每個玻璃表面著色。
- 使用 SF 排版與系統文字樣式。
- 在新增容器之前，先使用字重與間距建立層級。
- 讓內文避開高度折射或繁雜的玻璃。
- 不要僅依賴色彩；保持足夠的對比。
- 尊重系統強調色、外觀與玻璃色調。

## 視窗狀態與調整大小

設計與測試：

- 作用中、key、主視窗與非作用中狀態
- 精簡、預設與寬螢幕寬度
- 收合或隱藏的側邊欄
- 選用檢查器
- 工具列溢位
- 長標題與在地化標籤
- 空白、載入中、已有資料與錯誤內容
- 滑鼠懸停、按下、焦點、選取、拖曳與停用狀態

非作用中視窗必須連貫地降低強調程度。自訂材質絕不能比原生外框更喧賓奪主。

## 協助工具與個人化

- 搭配「減少透明度」，提供不透明或穩定的背景。
- 搭配「增加對比」，保留窗格邊界、選取、焦點、圖示與文字。
- 搭配「減少動態效果」，不要依賴變形或彈跳來解釋狀態。
- 為每個僅有符號的動作提供協助工具標籤。
- 保留鍵盤巡覽、功能表指令、焦點框與 VoiceOver 順序。
- 測試完整的使用者自選玻璃色調範圍。
- 當背景色彩與折射改變時保持內容易於理解。

## 修正對應

| 如果設計具有… | 將其變更為… |
| --- | --- |
| 圓角內部應用程式外殼 | 直接置於系統視窗內的內容與窗格 |
| 內縮側邊欄卡片 | 全高來源清單窗格與共享分隔線 |
| 每個區段周圍都有卡片 | 間距、標題、原生區段或分隔線 |
| 每個區塊背後都有玻璃 | 導覽、指令與暫態 UI 上的原生玻璃 |
| 每個工具列圖示都有藥丸形狀 | 少量原生工作群組 |
| 預設使用浮動檢查器 | 相鄰檢查器窗格 |
| 表格周圍的儀表板磚塊 | 具備資料列與欄的單一原生表格 |
| 自訂標題橫幅 | 原生視窗標題與工具列 |
| 固定模糊/不透明度配方 | 自適應語意系統材質 |
| 僅有淺色模式的模型 | 淺色、深色、非使用中、著色、減少透明度與調整大小狀態 |

## 最終視覺檢驗問題

請自問：「若移除裝飾性的圓角半徑、筆畫與陰影，介面是否仍具備清晰的原生層級？」

若否，代表結構尚未確立。在新增材質之前，先修正窗格與元件層級。
